# ADR 0001: 補足は追記のみで上書きしない。アプリは AI を呼ばず、補足は外から CLI で書く

## 背景

メモは「リンクと一言」だけを素早く溜める。意味づけ（リンク先の引用、考察、話題）はあとから AI が付ける。
同じメモを日をおいて考え直すことがあり、そのとき前の考察が消えると「その時点で何を考えたか」が読めなくなる。
また、AI の呼び出しをアプリに組み込むと、モデルや認証の変更のたびにアプリを直すことになる。

## 決定

- 補足（Annotation）は追記だけにする。既存の補足を編集・削除する API は作らない。後日の考察は新しい補足として足し、時刻つきでタイムラインに積む
- 補足の種別は `quote` / `analysis` / `memo` の 3 種。それ以外は 400。本文は必須で空は不可。`author` は `ai`（既定）か `human`
- アプリは AI を呼ばない。補足は外から `note annotate`（HTTP API の `POST /api/notes/{id}/annotations`）で書く
- メモ本体の削除（`DELETE /api/notes/{id}`）だけは残す。登録直後の「元に戻す」に使うため

## 捨てた案

- **補足を編集できるようにする**: 考え直すたびに前の考察が上書きされ、時点ごとの考察が残らない
- **アプリが AI を呼んで自動で補足を付ける**: 認証・モデル選択・失敗時の再試行がアプリに入る。補足の付け方（どの資料を見るか）も AI 側で変えたいので、アプリの外に置く

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 補足の種別の追加。`author` の値の追加。画面での補足の見せ方
- **壊すと危ない**: 補足を後から書き換えられるようにすること。タイムラインが「時点ごとの考察の積み重ね」であることを前提に画面とログを組んでいる。アプリに AI 呼び出しを入れると、書き手がサーバ 1 つという前提（ADR 0002）の外にも書き込み経路が増える
