# ADR todo-0019: 長期は状態として持ち、フォーカスの帯の上の閉じた枠に置く

## 背景

何か月もかかる仕事（例: 切替ドキュメント一式）を忘れないよう、フォーカスに置きっぱなしにしていた。実際に手を動かすのは、そこから切り出した作業（レビュー会の準備、日程の調整など）で、親はフォーカスに居ても「次にやること」ではない。そのため、フォーカスが常に 1 件余分に埋まっていた。

## 決定

**長期は状態にする（`StateLong`）。** 長期にすると着手順から外れ、フォーカスの印も落ちる。外すと着手順の先頭（フォーカスのすぐ下）に戻る。戻り先は常に同じなので、元の位置を覚えておく必要が無い。ADR todo-0005 がフォーカスを状態にしなかった理由（外したときの戻り先が分からない）は、ここには当てはまらない。

**手を動かす作業は子として切り出す。** 子は `Parent` に長期のタスクの ID を持つ。親になれるのは長期のタスクだけで、長期のタスクは子になれない（1 段だけ）。

> 「親になれるのは長期のタスクだけ・1 段だけ」の部分は ADR todo-0020 が置き換えた。

**枠はフォーカスの帯の上に置き、既定で閉じる。** 長期のタスクが無いときは枠ごと出さない。閉じていても見出しに中身を出し、未完の子が 0 件の長期があれば見出しを黄色にして「次の一手なし」と出す。開くと長期ごとに次の一手（未完の子のうち着手順でいちばん上のもの）と子の件数が出る。

> 「枠はフォーカスの帯の上」の部分は ADR todo-0022 が置き換えた。長期は下の畳める区画へ移り、注意は条件で引く。

**入口はフォーカスと同じ場所に並べる。** 開いた行の「長期にする」「長期を外す」「子を追加」「長期 ▾」と、CLI の `long` / `unlong` / `--parent` / `parent`。ドラッグでは入れない。

## 捨てた案

- **フォーカスと同じく印で持つ**: 着手順に残るので、長期のタスクが並べ替えやスコープの対象になり続ける。帯の外に出す意味が薄れる
- **帯の中に灰色の 1 行で出す**: 実装は小さいが、次の一手が見えないので目印から先に進まない
- **チケット番号が名前に入っているタスクを自動で子にする**: 同じ番号でも別件の作業が混ざり、次の一手がずれる
- **長期の枠へのドラッグ**: 枠は閉じているのが普段の状態で、長期が 0 件だと出てもいないので、落とす先にならない

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 枠の見た目、閉じたときの見出しの文言、次の一手の選び方（今は着手順でいちばん上の open の子）
- **壊すと危ない**: 長期が `openIndexes` に入らないこと。入ると並べ替えやフォーカスの位置計算に長期が混ざり、ADR todo-0012 の並びが崩れる
- **壊すと危ない**: 親が長期であることを `SetParent` と追加の両方で確かめること。子の追加（`AddChild`）は、親の確認・作成・親の設定を同じロックの中で 1 つのイベントとして行う。分けると、親が途中で長期でなくなったときにタスクだけが残り、undo 1 回で子が消えなくなる
