# ADR todo-0023: 期限前の行は薄く、3 日以内は琥珀の線、止まっている日数は 5 日から色を付ける

## 背景

着手順の行が増えると、どの行が「今動かすべきもの」か見分けにくい。期限が先の行も「あと N日」と同じ重さで並び、期限前の行にも「止まって N日」が付いて色を持つ。ADR todo-0021 の段階（1・2・3・5・8 日で、2 は枠、3 は琥珀）は、期限の近い行の琥珀と区別が付かなかった。

## 決定

**期限が 4 日以上先の行は文字色を一段薄くする。** 着手順・フォーカス・スコープ外が対象。1〜3 日先（`soon`）は薄くしない。期限が明日以降の行の札は「あと N日」ではなく「M/D から」と読む。サーバの `due_label` がこの文言を返すので、CLI の一覧も同じ文言になる（CLI は日付が重複するため `[11/4 から]` と出す）。

**止まっている日数は、期限が来るまで出さない。** 期限が今日より後なら、人の補足があっても数えない。期限の日が来てから、期限と人の最新の補足の遅い方から数える（todo-0021 の数え方のまま）。

**期限まで 1〜3 日は `due_class: soon`。** 左端の線（3px）と期限の札を琥珀（`--near`）にする。背景は塗らない。今日（`today`）は今のまま背景も塗り、線の太さではなく背景で区別する。4 日以降は `near`（スコープ内）か `plain`（スコープ外）のまま色を付けない。境目（3 日）はサーバの `taskapi.SoonDays` が持ち、画面は class を見て色を付けるだけ。

**止まっている日数の段階は 1・5・8。** 1〜4 日は枠も色も付けず文字だけ（`--muted`）。5 日から紫、8 日から赤（todo-0021 の色のまま）。todo-0021 の段階 2・3 は無くなる。

**チケット番号の札・親の札・見出しの件数。** 名前の先頭が `[A-Z]+-\d+` なら、番号を名前の左の札に分けて描く（データの名前は変えない。編集中は元の名前のまま）。親の札は、親の名前の先頭のチケット番号と続く空白を飛ばし、子の名前と共通する先頭部分（空白か `）` の直後で切る）も飛ばして 6 文字にする。見出しの件数は「超過 N ・ 今日 N ・ ほか N」と言葉を付ける。最も近い期限（今日より後）の行は、サーバが応答の `next_due` に入れる。

## 理由

- 4 日以上先の行を薄くする: 色の付いた行（超過・今日・3 日以内）だけが目に入るようになる。期限前の行に「止まって」は不自然で、期限が来てから数え始めるほうが「放置している」の意味に合う
- 3 日以内を琥珀にする: 今日になってから気づくのでは遅く、数日前から着手の準備ができる。今日との差は背景の有無で残す
- 1〜4 日を文字だけにする: 琥珀の線と札が期限の近さを表すので、止まっている日数は琥珀を使わず、5 日から別の色（紫・赤）で違う意味を表す

## 捨てた案

- **期限前でも止まっている日数を出す**: 期限前の行に「止まって N日」の赤や紫が付き、期限の色と混ざる
- **3 日以内を既存の `near` のままクライアントで判定する**: 境目をサーバとクライアントの両方が持つことになり、ADR todo-0011 の「画面は class で色を付けるだけ」に反する
- **todo-0021 を superseded にする**: 数え方・対象・触った印の決め方は変えていない。変えたのは段階の色だけ

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 3 日・5 日・8 日の境目、色、札の文言
- **壊すと危ない**: 期限前の行に止まっている日数を出さないこと（期限の色と意味が混ざる）。`soon` の境目をサーバだけが持つこと
