# ADR todo-0024: 話題はタスクの 1 項目で、着手順を話題で区切って見せるのは表示だけにする

## 背景

着手順は 1 本の列で、仕事の種類（青環離 / FUNDINNO / 報告と調整 / 学習）が混ざる。種類ごとにまとめて眺めたい場面があるが、種類ごとに別の列を持つと「次にやること」が複数になり、着手順が 1 本であるという前提（ADR todo-0012 のフォーカス、todo-0020 の親子の並び規則）が崩れる。

## 決定

- 話題は `Task.Topic`（文字列、空は話題なし、JSON は `omitempty`）。前後の空白を落とし、20 文字（`task.MaxTopicLen`、文字数で数える）まで。改行は不可
- 変更は `topic_set` イベント（`from_value` / `to_value` が新旧の話題）として残し、undo で戻せる。話題なしへ戻す undo も効く
- API は `PATCH /api/tasks/:id` の `topic`（空文字で解除）。一覧の応答の `topics` に、使われている話題を重複なしで返す（キュー（フォーカス含む）で最初に出た順、続けて長期・待ち・いつか）。入力候補用
- CLI は `todo topic <ID> <話題|->`、`todo "名前" --topic 話題`。`todo list` は区切らず、行の末尾に `{話題}` を付ける（`#` は GitHub の番号と紛らわしい）
- 区切りは**表示だけ**。画面のトグル「話題で分ける」（既定オフ、`localStorage` の `todo-order.group-by-topic`）をオンにすると、着手順のうちスコープ内でフォーカス以外の行だけを話題ごとの小見出し（話題名と件数）の下に並べる
  - 話題の並びは「その話題で着手順の一番上にある行の順」。各話題の中は着手順のまま。話題の無い行は最後の「話題なし」
  - フォーカスの帯は区切らない（いつも一番上）。長期・スコープ外・待ち・いつか・完了の区画も区切らない
  - 位置の番号は出さない（既存方針）
  - 区切っている間は着手順の行にハンドルを出さず、着手順への drop を受けない。トグルの下に「分けている間は並べ替えできない」と出す
  - 行に話題の札は出さない。見出しで足りるのと、行を重くしないため
- 話題の編集は開いた行の詳細と右の詳細の箱の 1 行入力（`datalist` に既存の話題を候補表示）。打ち終わり（0.9 秒）と離れたときに保存する

## 捨てた案

- **話題ごとに別の列（着手順を分割）**: 次にやることが話題の数だけできて、フォーカス・親子の位置規則と両立しない
- **区切り中もドラッグを許す**: 見出しをまたぐ drop が「話題を変える」のか「位置を変えるだけ」なのか決まらず、着手順は 1 本という前提で意味を持たせられない
- **話題の自動推定・note からの自動付与**: 誤った分類が静かに入る。別の判断として扱う
- **話題の改名・一括操作**: 使われ方が分かるまで作らない。今は 1 件ずつ付け直す
- **行に話題の札**: 区切った表示では見出しと重複し、区切らない表示では行が重くなる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 上限の 20 文字、見出しの見た目、`topics` に長期・待ち・いつかの話題を含めること
- **壊すと危ない**: 着手順（`Order`）が話題と無関係に 1 本のままであること。区切りは画面の並べ替えだけで、API の `queue` の順は変えない。区切り中に着手順へ drop を通すと、画面の見た目の位置と `Order` の位置がずれる
