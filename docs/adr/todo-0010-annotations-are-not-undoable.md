# ADR todo-0010: タスクの補足は undo の対象にしない

## 背景

メモから作ったタスクには、AI が引用や考察を補足として足す（`todo annotate`）。
undo は「最後のイベントの逆を当てる」ので、補足もイベントにすると、人が直前の自分の操作を取り消そうとしたとき、
先に AI の補足が消えてしまう。人が取り消したいのは自分の操作で、AI が足した補足ではない。

## 決定

- 補足は `annotated` イベントとして記録するが、undo の対象にしない。undo は補足のイベントを飛ばし、その前の取り消せる操作を対象にする。取り消し可能な件数（`undoable`）にも数えない
- 補足は追記専用で、編集・削除の API を持たない（メモの補足と同じ。ADR note-0001）
- スナップショットを丸ごと書き戻す取り消し（棚上げの取り消し）は、書き戻すタスクに現在の補足を引き継ぐ。さもないと、棚上げの後に付いた補足がスナップショット側の空の状態で消える
- 補足の書き手は、既存のタスク API と同じくリクエストの `actor`（CLI では `TODO_ORDER_ACTOR`）で決める

## 捨てた案

- **補足も undo できるようにする**: 人の undo のたびに AI の補足が巻き込まれて消え、人は補足を取り消すつもりがないのに順番に当たってしまう。補足を取り消したいときは、あとから新しい補足で訂正すればよい
- **補足を別のイベントログに分ける**: undo の走査からは外れるが、時系列で経緯を読むときに 2 本のログを突き合わせる必要が出る

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 補足の種別の追加。画面での補足の見せ方
- **壊すと危ない**: `undoable` に `annotated` を入れること。タスク全体を丸ごと書き戻す処理を新しく足すとき、補足を引き継がないこと（補足が消える）
