# ADR todo-0026: 入力欄は書き換えない要素にし、画面は同じルート要素へ描き直す。ドラッグのプレビューだけ要素を直接動かす

ADR todo-0025（Preact と htm を使う）の下で、4 画面を移す間に決まったこと。todo-order と note-stock の両方の画面に関わるので、番号は todo 側に置く。

## 背景

ADR todo-0025 は「描き直しで変わっていない行の DOM を残す」ために Preact を入れた。しかし行を key で保つだけでは、入力中の欄は守れない。

- 欄の value を状態から描くと（controlled）、ポーリングの応答や別の欄の操作で描き直すたびに、打っている途中の文字・フォーカス・キャレットが状態の値で上書きされる。日本語入力の変換中は特に壊れやすい
- 画面を見せるたびに作り直すと、todo 一覧との行き来で書きかけのメモや追加の下書きが消える
- ドラッグは、ブラウザが掴んでいる行の要素そのものを `dragend` まで文書の中に置いておく必要がある。Preact は行をまたぐ並べ替えで別の要素を作るため、掴んだ要素が文書から外れて `dragend` が来なくなるおそれがある

## 決定

**入力欄は書き換えない要素（uncontrolled）にする。** 文字は要素が持ち、Preact は value も子も書かない。保存と読み出しは要素から文字を読んで行う。外から変わった値（ポーリングで届いた盤面・別の画面での変更）は、欄が編集中（フォーカスがある・保存中・未保存の文字がある）でなければ欄に流し込み、編集中なら流し込まず、保存が済んでから追いつく。パネルと名前は、何かが握っている間（`state.busy`）は前の task を表示したままにし、離れた後の最初の描画で追いつく（`detail.js` の `useHeld`）。

**画面は、ルーターが見せるたびに同じルート要素へ描き直す。** `mount` は枠（または何も）を作らずルート要素を覚えるだけで、`show` のたびに同じルート要素へ `render` する。要素を作り直さないので、部品の状態と入力の文字が画面を離れている間も残り、追加ダイアログへ貸し出して閉じても書きかけが残る。

**ドラッグ中のプレビューだけは、掴んだ行の要素を素の JS が直接動かす。** 落とす位置は動かした要素から読み戻さず `state.drag.dest` に持つ。`render()` は描く前に要素を元の場所へ戻し、描いた後に `dest` へ動かし直す。これが ADR todo-0025 の「Preact が描く要素を素の JS から直接書き換えない」の唯一の例外で、Preact だけでプレビューを描く形への置き換えは [#140](https://github.com/rengotaku/workbench/issues/140) に置く。

## 捨てた案

- **入力欄を controlled にして、入力のたびに状態へ書き戻す**: 変換中の文字・キャレットの位置を状態と同期させる処理が欄ごとに要り、描き直しの種類が増えるほど壊れやすい。要素に文字を持たせる方が、描き直しの回数と無関係に守れる
- **画面を見せるたびに作り直し、下書きは別に保存して戻す**: 保存と復元の経路が画面ごとに増える。同じルート要素へ描き直せば、部品の状態も入力欄も何もしなくて残る
- **ドラッグのプレビューも Preact で描く**: 行をまたぐと別の要素が作られ、掴んだ要素が文書から外れて `dragend` が来ないおそれがある。確かめて直すのは #140 に回した

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 流し込みの判定（何を編集中とみなすか）の細部。ドラッグのプレビューの実現方法（#140 で置き換える）
- **壊すと危ない**:
  - 入力欄に value を書かない。書くと描き直しのたびに打っている文字・フォーカス・キャレットが消える
  - `render()` の前後で、動かした行の要素を戻して動かし直す手順。省くと、描き直しがドラッグ中の位置を崩す、または掴んだ要素が外れて `dragend` が来なくなる
  - `mount` で枠を作り直さない（作り直すと部品の状態が消える）
  - 遅れて届いた応答を連番で捨てる（`loadSeq` / `seq` / `topicSeq` / `pendingSeq`）。外すと、古い絞り込みの応答が新しい画面の上に描かれる
