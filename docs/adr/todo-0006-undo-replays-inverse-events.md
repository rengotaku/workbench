# ADR todo-0006: 取り消しはサーバ側でイベントを逆適用する

## 背景

操作を間違えたときに戻したい、という要望が出た。

このアプリの書き手は画面と CLI（人と AI）の 2 つある。クライアント側に取り消しのスタックを持つと、画面で行った操作しか戻せず、CLI からの操作が混ざった時点で列が食い違う。

## 決定

取り消しはサーバ側で行う。`events-YYYY-MM.jsonl` の末尾から未消費のイベントを 1 件取り、その逆操作を適用する（LIFO）。画面と CLI の操作は 1 本の列として扱われる。

逆操作もイベントとして記録するが、**記録と同時に消費済みとして印を付ける**（`recordSpent()`）。元のイベントも消費済みにする。

## 捨てた案

- **クライアント側の undo スタック**: 画面の操作しか戻せない。CLI と AI の操作が抜ける
- **逆操作を普通のイベントとして積む**: 実装して実際に壊れた。逆操作が次の取り消し対象になり、「戻す → やり直す」を交互に繰り返して先へ進まなくなる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 遡れる件数、取り消しの対象にするイベント種別、やり直し（redo）を後から足すこと
- **壊すと危ない**: 逆操作を消費済みで記録すること。ここを外すと往復のループが再発する。また、イベントログが追記専用であること（過去のイベントを書き換えると逆適用の前提が崩れる）
