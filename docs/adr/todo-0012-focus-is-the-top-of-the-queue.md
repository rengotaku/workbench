# ADR todo-0012: フォーカスは着手順の先頭。帯にだけ出し、ドラッグで付け替える

## 背景

ADR todo-0005 では、フォーカスを位置に影響しない印にした。帯に出しつつ着手順の元の位置にも残し、`◎` を付けていた。

使ってみると、フォーカスと並び順が食い違った。優先度は並び順で表していて、フォーカスしたタスクは並び順でも一番上にあるべきものだった。実際、フォーカスした直後に手で上へ動かしていた（T070 は「フォーカスに入れた」の直後に「順序変更 10 → 2 番目」）。帯はタスク名だけの行で、押すと下の着手順の同じ行へ飛んで開くので、同じタスクが 2 か所に出て、どちらを触ればよいか迷った。フォーカスが 0 件だと帯が消え、入れる場所も見えなかった。

## 決定

**フォーカス中のタスクは、着手順の先頭にまとまる。** `renumber` が着手順を「フォーカス中 → それ以外」の順に並べ直す。それぞれの中の順は保つ。フォーカス・並べ替え・待ちからの戻り・undo のどれを通っても、この並びは崩れない。この並びになる前に書かれたデータも、読み込み時に並べ直す。

**フォーカスを付け外しすると位置も動く。** フォーカスするとフォーカスの末尾へ、外すと一覧の先頭（フォーカスのすぐ下）へ移る。ドラッグで落とした場合は、その位置に入る（`FocusAt`、API は `/focus` の `to`）。位置はそのタスクが属するまとまりの中に収める。`Reorder` はまとまりの境目を越えない。越えるのはフォーカスの付け外しだけ。

**undo は位置も戻す。** フォーカスのイベントに移動前後の位置を持たせ、取り消すと印と一緒に元の位置へ戻す。

**画面ではどのタスクも 1 か所にだけ出す。** フォーカス中のタスクは帯にだけ出し、下の一覧には出さない。帯の行は一覧と同じ行で、その場で開く。帯は 0 件でも表示し、行を落とす場所にする。

## 捨てた案

- **位置を動かさず、食い違いを印で知らせる**: 直す作業が手で残る
- **フォーカスをなくし、着手順の上から N 件を帯に出す**: 食い違いは起きないが、2・3 件目を飛ばして 4 件目に集中する使い方ができない
- **帯と一覧の両方に同じタスクを出し、帯の中でも開けるようにする**: 同じタスクが 2 か所に出て、どちらで触ったか迷うことが残る

ADR todo-0005 が帯へ移す案を捨てた理由は「外したとき何番目だったか分からなくなる」だった。外すときは一覧の好きな位置へ落とせるし、ボタンで外せば一覧の先頭に入るので、この心配は当たらない。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: ボタンで外したときに入る位置（今は一覧の先頭）、帯の見た目、0 件のときの案内文
- **壊すと危ない**: `renumber` がフォーカス中のタスクを先頭に寄せること。ここを外すと、resume や undo のあとに食い違いが戻る
- **壊すと危ない**: 画面がドラッグの位置を「すぐ上の行の次」として、フォーカスを含む着手順全体に対して送ること。一覧の行数で数えると、帯の件数やスコープ外で畳んだ行の分だけずれる
