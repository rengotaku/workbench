# ADR todo-0001: 着手順はカンバンではなく1本の順序リストで持つ

## 背景

管理したいのは「次に何をやるか」。既存の運用でも順序は人が決めており、見積や期限から機械的に導出していない（依存・判断待ち・切替日が絡むため）。

一方でカンバン形式も候補に挙がった。ボード表示のツールは多く、見た目の馴染みもある。

## 決定

**1 本の順序付きリスト**を正とする。状態を列に割らない。

- 上から順に取る前提で、位置そのものが優先度を表す
- 止まっているもの（相手のボール）だけ「待ち」として 1 区画に出す
- 完了は「今週完了」として直近の月曜以降だけ残す

## 捨てた案

- **カンバン（列 = 状態）**: 列の中の順序を主張しないため、「次にどれを取るか」が形として出ない。20 枚ある「未着手」列は着手順の情報を持たない
- **列を状態として持つ**: Backlog 側に既にステータスがあるので、列を作ると同じ情報を 2 か所で管理することになる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 区画の見出し・並び順の表示方法・完了を残す期間
- **壊すと危ない**: 順序が 1 本であること。順序を状態別に分けると「次に取るもの」が決まらなくなる
