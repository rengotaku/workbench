# ADR 0003: CLI はサーバ経由でのみ書き込み、データファイルを直接触らない

## 背景

人はターミナルから、AI も同じコマンドから操作する（`mr` と同じ形）。一方で画面もブラウザから書き込む。

書き手が複数になると、イベントログの記録漏れと排他制御が二重になる。

## 決定

- **書き手はサーバだけ**。CLI は REST を叩く
- **サーバが落ちていればエラーで止まる**。ローカルファイルへ退避しない
- 誰が変更したかは `TODO_ORDER_ACTOR` で宣言し、イベントに人 / AI として記録する

## 捨てた案

- **CLI が JSON ファイルを直接読み書きする**: サーバが落ちていても使える利点はあるが、2 つの書き手が同じファイルを触ることになる。イベント記録の漏れが起きうる
- **不通時にローカルへ退避して後で同期する**: 正本が 2 つになる。旧台帳を畳んだ目的そのものを崩す
- **MCP サーバを同梱する**: localhost に REST があるなら層を増やすだけ。必要になってから足せる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: エンドポイントの形・CLI の出力整形・`--json` の有無
- **壊すと危ない**: 書き手が 1 つであること。不通時のフォールバックを足すと正本が割れる
- **壊すと危ない**: 存在しない ID・既完了 ID をエラーで返すこと。no-op を成功として返すと、誤った ID の操作が成功したように見える
