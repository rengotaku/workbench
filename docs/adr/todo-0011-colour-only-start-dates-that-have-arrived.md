# ADR todo-0011: 色は着手日が来た行だけに付ける。期限が近いだけでは付けない

## 背景

着手順の行頭の帯は「スコープに入っているか」で色を決めていた。期限なしのタスクは常にスコープ内なので琥珀になり、10/15 時点では 9 件中 8 件が琥珀だった。帯が何も知らせていない状態になっていた。期限チップは `due_class` で色を決めていたので、期限なしの行は「帯が琥珀、チップが灰」と食い違ってもいた。

使い方を確かめると、期限は完了の締切ではなく「この日ごろに着手する」目安だった。優先度は並び順で表し、優先するものは手で上へ動かす。並び順は自分で動かすので見ればわかる。日付は放っておいても進むので、「着手日が来たのに下のほうに置いたまま」という見落としが起きる。

## 決定

**帯とチップの色は、着手日が来た行だけに付ける。** 過ぎたら赤、今日なら琥珀。まだ先の日付と期限なしは色を付けない。帯とチップは同じ基準にする。

**今日と過ぎたものを API で分ける。** `due_class` に `today` を足す。それまでは今日も `over` だった。`overdue` は今日も true のままにし、見出しの件数（超過・期限内・外）の区切りは変えない。

**スコープの働きは変えない。** スコープより先の行を末尾に畳むこと、範囲外の行を薄くすること、`Reorder` がスコープ内の期限を飛び越えたときに記録することはそのまま。スコープが決めるのは「どこまで見せるか」で、色は決めない。

## 捨てた案

- **帯を `due_class` の `near` で琥珀にする**: 期限を締切とみなす案。着手の目安として使うと、7 日以内のものがほぼ全部琥珀になり、いまと同じく区別がつかない
- **帯をやめ、チップの色だけにする**: 並び順の邪魔はしないが、下のほうに置いたまま着手日が来た行が一覧で目立たない
- **着手日の 1〜2 日前から琥珀にする**: 予告にはなるが、準備が要るタスクがあまり無い運用では色の付く行が増えるだけ

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 今日を琥珀にする色の選び方。見出しの件数の区切り（今は帯の色と一致していない）
- **壊すと危ない**: 帯とチップを別の基準に戻さないこと。食い違うと、どちらを信じればよいか分からなくなる
- **壊すと危ない**: 期限なしの行に色を付けないこと。着手順は期限なしが多く、色を付けると帯がまた全部同じ色になる

## 追記（2026-10-15, #33）

見出しの件数を帯と同じ区切りにした。今日のタスクが件数では赤、行では琥珀と食い違っていたため。赤は目安日を過ぎたもの、琥珀は今日のもの、灰はそれ以外を数える。JSON のキー（`over` / `near` / `rest`）は画面と CLI が読んでいるので名前を変えず、`near` を「今日」の件数として使う。CLI の表記は「超過 / 今日 / その他」にした。
