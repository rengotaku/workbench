# ADR todo-0022: 長期は下の畳める区画へ移し、注意は位置ではなく条件で引く

## 背景

ADR todo-0019 の長期の枠は、閉じていても一覧の最上部にあった。長期の仕事は見守りたいが、毎日いちばん上を占めてほしくはない。注意は置き場所で引くのではなく、見る必要が出たときに条件で引く（GTD の週次レビュー、Linear のプロジェクトの更新と同じ考え方）。

## 決定

**長期の区画は、スコープ外・待ち・いつか・今週完了・今週やめたと同じ、下の畳める区画にする。** 並びはその先頭（スコープ外の上）。既定は閉じで、`localStorage` のキー `todo-order.long-open` は変えない。見出しの補足は「次に見る日が来たら上に出る」。`#T051` のリンクは区画を開く。ADR todo-0019 の「枠はフォーカスの帯の上」の部分を置き換える。

**長期のタスクに「次に見る日」（`review_on`）を持たせる。** 長期にしたとき、空なら今日 +7 日を入れる。見直す操作（`POST /api/tasks/:id/review`、`todo review`）は、日付を省くと今日 +7 日を置き、見直した時刻（`reviewed_at`）を記録する。新しいイベント `review_set` で、通常の undo で戻せる。`review_on` を持たない既存の長期は「見直し日が来た」と数える。一度上に出て、日付が決まる。

**見直しが要る条件は 3 つで、どれかを満たせば要る。** 判定はサーバ（`taskapi`）が行い、`needs_review` と理由（`no_next` / `review_due` / `stalled`）を返す。画面と CLI は再計算しない。

- 次の一手が無い（未完の子が 0 件）
- 次に見る日が空、または今日以前
- 止まっている。ADR todo-0021 の止まっている日数が 8 日以上

**長期では、見直しを「人が触った」印に数える。** ADR todo-0021 は人の補足だけを触った印にしている。長期は補足を書く機会が少なく、見直しの操作そのものが「見た」ことを表す。そのため長期に限り、止まっている日数の起点を「ADR todo-0021 の起点と、見直した時刻の遅い方」にする。これを数えないと、見直した直後でも止まっていると出続ける。

**要見直しの長期は、フォーカスの帯の上の「長期の見直し N」の帯に出す。** 該当が無いときは帯ごと出さない。1 件 1 行で、理由の札と「見直した」を置く。「見直した」は既定の +7 日を送る。次の一手が無いままのものは、見直しても行が残る。長期の行（区画の中）には、期限チップの位置に「見る M/D (曜)」のチップを置き、日付の指定と +1週間・+2週間・+1ヶ月のメニューで決める。

## 捨てた案

- **「長期」を「プロジェクト」に呼び替える**: Backlog のプロジェクトや cw のプロジェクトと言葉がぶつかる
- **長期の一覧を右ペインに置く**: 右ペインは詳細の場所で、長期の一覧を置くと詳細と取り合う。条件で上に出す方が、見る場所を増やさない
- **最上部の枠を閉じたまま残し、見出しだけを賢くする**: 位置が最上部のままなので、毎日いちばん上を占める問題が残る

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 既定の +7 日、止まっていると見る 8 日、帯と札の見た目と文言、区画の並び
- **壊すと危ない**: 判定を画面や CLI に持たせること。3 つの条件がずれると、同じ長期が画面では要見直し、CLI では平穏、ということが起きる
- **壊すと危ない**: `review_on` が空の長期を「見直し日が来た」と数えること。古いデータが見直されずに沈む
