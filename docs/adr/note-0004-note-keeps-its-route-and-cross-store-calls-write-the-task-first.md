# ADR note-0004: 行き先はメモが持ち、2 つのストアをまたぐ操作はタスク先行＋source_note_id で冪等にする

## 背景

人は「次の進捗レポートで AI に拾ってほしいもの」をメモに入れる。AI はメモを読み、行為なら todo を作り、記録ならメモのまま残す。
これまで「補足待ち」は補足が 0 件のメモを指していた。だが記録として残すだけのメモには補足を付けないことがあり、
その場合「拾い済み」と「まだ」を区別できない。また todo を作ったメモが、どのタスクになったのか辿れなかった。
タスクとメモは別のディレクトリ・別のファイルで持っており、1 回の書き込みで両方は更新できない。

## 決定

- Note に `triaged_at`（AI が拾った時刻）と `route`（`to`: `todo` か `record`、`task_id`: `todo` のときだけ）を持たせる。補足待ちは「`triaged_at` が空」で判定する
- Task に `source_note_id` を持たせ、どのメモから作ったかを記録する
- 行き先を決める API は `POST /api/notes/:id/route`。task ストアと note ストアの両方が要るので `internal/noteroute` に置き、noteapi と taskapi の責務は変えない
- todo を作る手順は「タスクを作る → メモの `triaged_at` と `route` を更新する」の順。メモの更新に失敗してもタスクは残り、再実行では同じ `source_note_id` のタスクがあればそれを使う（新しく作らない）。同じメモへの同時リクエストは mutex で直列にする
- すでに行き先があるメモに同じ行き先でもう一度呼ぶと、現状をそのまま返す。違う行き先なら 409 にする
- 起動時の移行: 補足が 1 件以上あり `triaged_at` が空のメモは、最初の補足の時刻を `triaged_at`、`route` を `record` にする。変更があったときだけ保存し、2 回目の起動では何も変えない

## 捨てた案

- **2 つのストアを 1 つにまとめる**: 手順の問題は消えるが、ディレクトリ・ロック・ログがそれぞれ独立しているという前提（ADR todo-0002、note-0002）と、片方だけ別サーバに出せる構成が崩れる。やることに対して変更が大きすぎる
- **人が画面のボタンで「このメモから todo を作る」**: 拾って行き先を決めるのは AI の仕事で、人は書き留めるだけという分担にしている。人用の入口を作ると、どちらが拾ったのか分からなくなる
- **メモを先に更新してからタスクを作る**: タスクの作成に失敗するとメモが「todo 行き」なのにタスクが無い状態になり、再実行で直すにも `task_id` が無い。タスクが先なら、失敗の残りは「タスクだけある」で、`source_note_id` で必ず回収できる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 行き先の種類の追加（`route.to` の値）。画面での行き先の見せ方
- **壊すと危ない**: タスクを先に作る順序（逆にすると、再実行で回収できない失敗が生まれる）。`source_note_id` でタスクを探す処理を外すこと（メモの更新に失敗して再実行するたびにタスクが増える）
- **既知の限界**: メモの更新に失敗したあと、再実行の前に人がそのタスクを消すと、再実行で同じメモから新しいタスクが作られる。メモの更新が済んだあとは、再実行は現状を返すだけなので増えない
