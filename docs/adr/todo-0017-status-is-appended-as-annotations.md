# ADR todo-0017: 状況は詳細欄ではなく補足として追記する

## 背景

状況を書き足す手段が、詳細欄（自由記述）の書き換えしかなかった。書き換えは前の状況を上書きし、いつ何が起きたかが残らない。
補足（ADR todo-0010、note-0001）は追記専用で時刻と書き手を持つが、画面から書けなかった。

## 決定

- 状況は補足として追記する。画面の開いた行に 1 行の入力欄を置き、`POST /api/tasks/:id/annotations` に `actor=human` で送る
- 補足の種別に `progress`（進んだ）と `blocked`（詰まり）を足し、`memo` と合わせて人が選べるようにする。CLI `todo annotate` も同じ 5 種を受ける
- 「待ち」の種別は作らない。待ちは既存の「待ちにする」で状態を変える。種別と状態の両方に待ちがあると二重になり、どちらが正か分からなくなる
- 詳細欄の挙動は変えない。補足の編集・削除と undo の扱い（ADR todo-0010）も変えない

## 捨てた案

- **詳細欄に日付つきで追記する**: 自由記述の中身を機械的に読めず、一覧に最新の状況を出せない
- **「待ち」の種別を足す**: 上記のとおり状態と二重になる

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 札の名前・色、一覧に出す件数、経過日数を強調する日数
- **壊すと危ない**: 人が書く状況に `actor=ai` を付けること（書き手の区別が崩れる）。`annotated` を undo の対象に入れること（ADR todo-0010）
