# ADR note-0003: 関連 URL は登録時にメモ本体へ固定し、本文から [N] で指す

## 背景

メモには、1 行の一言に対して関係するリンクが複数あることが多い（Slack のスレッドと Backlog のチケットなど）。
これまでは本文中の最初の URL だけを `url` に取り出していた。2 件目以降は本文にリンクとして出るだけで、一言のどの部分がどのリンクの話なのかを示す手段が無かった。
関連 URL を添えるのは、登録するときの本人。

## 決定

- 関連 URL は `Note.Links`（`n` / `url` / `label`）としてメモ本体に持つ。登録時にだけ受け付け、後から追加・編集する API は作らない
- 番号はメモごとに 1 から、送られた順に振る。登録後は変えない
- 本文からは `[N]`（半角の角括弧と 1〜4 桁の数字）で指す。URL の中に現れる `[N]` は参照として扱わない
- 関連 URL が 1 件以上あるメモでは、本文の `[N]` が件数を超えると 400 にする。関連 URL が無いメモでは検査しない（貼り付けた文章の `[1]` をはじかないため）
- URL は http(s) でホストのあるものだけを受け付ける
- 関連 URL の無いメモは `links` キーを持たない形で保存する。既存の `notes.json` はそのまま読める

## 捨てた案

- **補足に `kind: link` を足して追記する**: 後から足す場面には合うが、今回の使い手は登録時の本人だけ。補足に入れると、補足が 0 件のメモを指す「補足待ち」の判定が link の追加で崩れる
- **`#N` で指す**: 本文に GitHub の issue 番号（`owner/repo#131`）を書くことがあり、区別がつかない
- **番号をアプリ全体の通し番号にする**: 補足 ID と同じ通し番号だと `[57]` のような番号になり、本文で指すには長い
- **登録画面で空の行を飛ばして詰める**: 画面に出ている番号とサーバが振る番号がずれ、本文の `[N]` が別のリンクを指す。空の行がある間は保存しない

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 登録画面での入力の形（行の追加の仕方、ラベルの入れ方）。タイムラインでの関連 URL の見せ方。全角の `［N］` も参照として扱うこと
- **壊すと危ない**: 登録後に関連 URL を並べ替える・消す・番号を振り直すこと。本文の `[N]` は登録時の番号を前提に書かれているので、指す先が黙って変わる
