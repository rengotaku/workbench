# アーキテクチャ

現在の姿だけを書く。なぜそうしたかは `docs/adr/`（`todo-` 接頭辞）にある。

## 全体

```
  人 ──┬─ ブラウザ  http://127.0.0.1:8085 ─┐
       │                                    ├─ workbench-server ─┬─ tasks.json
  AI ──┴─ todo CLI ──── REST /api/… ────────┘   （唯一の書き手）    └─ events-YYYY-MM.jsonl
```

- **書き手はサーバだけ**。CLI もブラウザも REST を叩く。CLI はサーバが落ちていればエラーで止まり、ファイルを直接書かない
- サーバはループバック固定で認証を持たない。LAN へは出さない
- 画面は JS で描き、ビルド工程は無い。描画は Preact と htm（同梱の `web/shared/static/vendor/htm-preact.umd.js`）で、4 画面（todo 一覧・todo 追加・メモ追加・タイムライン）とも Preact で描く。ルーターとダイアログは素の JS（ADR todo-0025）。4 画面は 1 ページに置き、ルーター（`web/shared/static/js/router.js`）が表示を切り替える（ADR todo-0013）。サーバの `index.html` / `add.html` は空で、レイアウトがどのページにも全画面のルート要素（`data-view="…"`）と CSS・JS を置く。CSS は `.view-todo` / `.view-todo-add` の下に絞ってある。どのファイルがどの画面を描くかは「画面の描画」

## データ

`TODO_DATA_DIR`（既定 `~/.local/share/todo-order`、権限 0700）に 2 種類。

| ファイル | 性質 |
|---|---|
| `tasks.json` | 現在の状態。一時ファイルへ書いて rename で差し替える（途中状態を残さない） |
| `events-YYYY-MM.jsonl` | イベントの追記専用ログ。月ごとに分かれる |

イベントに理由を書くときも既存行を書き換えない。**同じイベント ID の新しい行を追記し、読み込み時に後の行が前の行を上書きする**。履歴そのものは編集されない。

## タスクの状態

```
   open（着手順） ──wait───────► waiting（相手のボール）
   open           ◄─────resume──┘  │
   open           ◄──resume────────┴─ someday（いつか）
   open           ──shelve───────────► someday
   waiting        ──shelve───────────► someday
   someday        ──shelve───────────► someday（Until を延ばすだけ）
   open / waiting / someday ──done──► done ──reopen──► open（着手順の末尾へ）
```

`someday` は「いまは着手順に置かないが、いつか再開したい」タスクの置き場で、`waiting` とは意味が違う（相手にボールを渡していない）。`open` と `waiting` の両方から `shelve` で入り、`resume`（既存の待ち復帰と同じ口）で `open` の着手順の末尾へ戻る。`done` にもなれる（棚上げ中に片付いた場合）。`Task.Until` は「この日までは見なくていい」日付で、`Due`（約束した期限）とは別のフィールドに持ち、超過表示も共有しない（ADR todo-0009）。`shelve` は `someday` のタスクにもう一度打つこともできる — 棚卸しで先送りを決めたときに `resume` を経由せず `Until` だけを延ばす口で、状態も `Order` も動かない。

`Order` は 4 状態を通した通し番号で、着手順 → 待ち → いつか → 完了 の順に振り直される。画面と CLI は `Order` の昇順に並べるだけでよい。

`remove` は唯一データを失う操作。取り除いた名前と期限を `removed` イベントに書いてから消すので、**何を消したかはログに残る**。そのタスクの他のイベントは孤児として残り、読む側（`Ask` 等）はタスクが存在しないイベントを読み飛ばす。`removed` 自体は例外で、スナップショットから名前を読んで質問キューに出す。ただし削除の時点で理由が入っていれば（画面で作ってから 1 時間以上たったタスクを消したとき）キューには出ない。`DELETE /api/tasks/:id` は本文の `reason` を任意で受け取り、CLI は送らない（ADR todo-0016）。

やめたタスクを読む口は `Store.Dropped(since)`。`tasks.json` にはもう居ないので、イベントログから組み立てて新しい順に返す。取り消した削除と、追加の取り消しが書く `removed` は除く（タスクが戻っている以上やめていない）。画面の「今週やめた」と `GET /api/tasks` の `dropped` がこれを読む。

`reopen` は完了を取り消して着手順の**末尾**へ戻す（元の位置には戻さない。その間にリストは動いているため）。完了の記録は消さず、`reopened` イベントが並ぶだけなので、経緯には「完了 → 復活」が残る。

## 画面の操作

| 操作 | どうなるか |
|---|---|
| 末尾の「＋ タスクを追加」・`N` | 追加画面（`/add` と同じ画面）をダイアログで開く。Enter で追加し、続けて足せる。Escape か × で閉じ、何か足していれば一覧を読み直す。ダイアログはルーターが追加画面のルート要素を一時的に貸し出す形（`router.js` の `lend`、`modal.js`）で、iframe は使わない |
| 区画の見出し（着手順・フォーカス・長期・スコープ外・待ち・いつか・今週完了・今週やめた） | 16px 太字。開閉する区画は矢印付きで、件数と今の補足（スコープ外は `期限 M/D 以降`、待ちは `最長 N日`、着手順は今週の範囲 `M/D〜M/D`）を並べる。着手順とフォーカスは常に開いているので矢印は無い |
| 「長期」の見出し | 開閉する。既定は閉じ。スコープ外の上に並ぶ。見出しの補足は「次に見る日が来たら上に出る」。状態は localStorage（`todo-order.long-open`） |
| 「長期の見直し」の帯 | 見直しが要る長期があるときだけ、フォーカスの帯の上に出る。名前を押すと長期の区画でその行が開く。「見直した」は次に見る日を 1 週間先にする |
| 長期の行の「見る M/D」チップ | メニューが開く: 月のカレンダー（期限のメニューと同じ部品）/ +1週間・+2週間・+1ヶ月。選ぶと次に見る日が変わり、見直した印が付く |
| 「スコープ外」の見出し | 開閉する。既定は閉じ。件数と、スコープ外が始まる日（`期限 M/D 以降`）を出す。状態は localStorage |
| 「待ち」の見出し | 開閉する。既定は閉じ。件数と、一番長く止まっている日数（`最長 N日`）を出す。状態は localStorage |
| スコープ外の並び | 期限の近い順。同じ日は着手順のまま。並べ替えるのは画面だけで、`queue` の順番（`Order`）は変えない |
| スコープ外の中でのドラッグ | 何も送らず元の位置に戻す。並びは期限で決まるため |
| 着手順とスコープ外の間のドラッグ | 位置を変えたうえで期限を変える。着手順へ入れるとスコープ最終日、スコープ外へ出すとスコープ外の初日。並べ替え（revision 付き）を先に送り、期限の PATCH は後に送る（ADR todo-0015） |
| 「いつか」の見出し | 開閉する。既定は閉じ（「今週完了」と同じ扱い）。見出しに全件数と、到来している件数を出す。状態は localStorage |
| 「今週完了」の見出し | 開閉する。既定は閉じ（記録であって待ち行列ではない）。件数は閉じたままでも出す。状態は localStorage |
| 「今週やめた」の見出し | 同じく開閉する。既定は閉じ、件数だけ出す。中身は削除のログから組んだ読み取り専用で、行に操作は無い（第 4 の状態ではない。ADR todo-0007）|
| 行を押す | 詳細が開く。専用のボタンは持たない。Enter / Space でも開く |
| 詳細の中の「フォーカス」（着手順の行のみ） | 上部の帯に入れる / 外す。入れるとフォーカスの末尾へ、外すと一覧の先頭へ移る（ADR todo-0012）。キーボードでドラッグの代わりをする口 |
| 詳細の中の「URLをコピー」 | そのタスクを開いた状態の URL（`/#T001`）をクリップボードへ入れる。AI にどのタスクの話かを伝えるときに貼る。ページは読み込み時に `#Txxx` の行を開く |
| 開いた行の名前・詳細 | その場で編集し、打ち終わり（0.9 秒）と離れた時に保存する。保存ボタンは無い |
| 詳細の中の「待ちにする」 | 渡した相手を聞いてから待ちへ移す（相手なしでは経過日数に意味が無いため必須） |
| 詳細の中の「いつかにする」（待ちの行のみ） | いつかへ移す。着手順の行では期限チップのメニューから行う |
| 詳細の中の「着手順へ戻す」 | 待ち・いつかから復帰（着手順の末尾へ）。**待ちから戻したとき**は通知を使わず、待ちの区画の元の位置に 1 行（`.resumed-stub`: 「T133 を着手順の末尾へ移した（高橋 へ 11/6 に渡していた分）」と「見る」「元に戻す」）を残し、着手順に入った行に色（`landed`）と「待ちから戻した」の札を付ける。行と札は出た直後に 3 回（0.5 秒ずつ）点滅する（`prefers-reduced-motion` では点滅せず色だけ）。次に書き込みが入る（この画面・端末のどちらでも。応答の `revision` と違う board を読んだら消す）か、スコープを変えるか、10 秒（`RESUMED_MS`）たつと消える。10 秒が来たとき行の中にキーボードフォーカスがあれば、フォーカスが外れるまで待つ。フォーカスがある間に元に戻す・次の操作で消すときは、フォーカスを戻したタスクの行（なければ待ちの見出し）へ移す。行き先は実際に最後尾のときだけ「末尾」と書く（子は親の直前に入るため）。ポーリングの描き直しでは消えない。「見る」は閉じた区画を開いてその行までスクロールする。「元に戻す」は `POST /api/undo?event=<resume のイベント ID>` で、渡した相手と渡した日を戻す。**いつかから戻したとき**は従来どおり通知に行き先と「見る」「元に戻す」を出し、行を 3 秒だけ色で示す。押さなければ画面は動かない |
| 経緯（1 行） | ホバーで全件が出る。縦に伸ばさないため一覧にしない |
| 経緯の「理由を書く」 | その場でイベントに理由を記録する（`todo why` と同じ口） |
| Cmd/Ctrl+Z ／ 通知の「元に戻す」 | 直前の変更を取り消す（`POST /api/undo`） |
| 行をドラッグ | 着手順が変わる。帯と一覧の間をまたぐとフォーカスが付け外しされ、落とした位置に入る（ADR todo-0012）。**位置の番号は画面に出さない**（順序はリスト自体が表しており、番号は動かすたびに古くなる） |
| チェックを入れる | 完了。今週完了へ移る |
| 完了行のチェックを外す | 復活。着手順の末尾へ戻る |
| 期限チップを押す（着手順の行）・詳細の箱の期限ボタン | メニューが開く（幅 380px まで。画面が狭ければ窓の幅から余白を引いた幅）。上から 月のカレンダー / 後ろにずらす（`+1日`・`+3日`・`+1週間`・`+2週間`・`+1ヶ月` を横 1 列に、名前の下に先の日付 `11/13` を添えて）/ 期限なし / いつかにする。カレンダーの日を押すとその日を期限にして閉じる（今の期限と同じ日なら何も送らず閉じるだけ）。+N は今日と今の期限の遅い方から数える（超過した期限から数えると、ずらしてもまだ超過のことがあるため）。メニューは todo 一覧のルート要素の直下に置き（CSS を届かせるため）、開いている間はポーリングを止める。ブラウザ標準の日付欄は使わない（ADR todo-0029） |
| 期限メニューのカレンダー | 見出し「2026年 11月」と前の月・次の月のボタン、曜日の見出し（日曜は赤系・土曜は青系）、7 列の日のボタン（6 週分。前後の月の日は薄く、押せる）。今日は枠、今の期限は塗り、今週（今日から今週の日曜まで。盤面の `today` と `scope_days`）は薄い塗り、未完了タスクの期限がある日には小さな点。開いた月は今の期限の月（期限がなければ今日の月）。キーボード: 開くと今の期限の日（無ければ今日）にフォーカス、矢印で日を動かす（左右 ±1 日・上下 ±7 日・PageUp/PageDown で ±1 ヶ月。月をまたげば表示も変わる）、Enter / Space で決める、Esc は閉じて札へ戻す。格子は `role="grid"`、各日は「11月12日（木）」の aria-label。カレンダーの外の項目は上下矢印で移る |
| 見出しの「話題で分ける」 | トグル。既定はオフ（今の 1 本の列）。オンにすると、着手順のスコープ内でフォーカス以外の行だけを話題ごとの小見出し（話題名と件数）の下に並べる。話題の並びは、その話題で着手順の一番上にある行の順。各話題の中は着手順のまま。話題の無い行は最後の「話題なし」。フォーカスの帯・長期・スコープ外・待ち・いつか・完了は区切らない。状態は localStorage（`todo-order.group-by-topic`）。トグルの下に「分けている間は並べ替えできない」と出す（ADR todo-0024） |
| 区切っている間の着手順の行 | ハンドルを出さず、ドラッグできない。着手順への drop も受けない（帯とスコープ外の中・間は今まで通り）。位置の番号は出さない |
| 開いた行・右の詳細の箱の「話題」 | 1 行入力（`datalist` に使われている話題を候補で出す）。打ち終わり（0.9 秒）と離れた時に保存し（`PATCH` の `topic`）、空にすると外れる。行には話題の札を出さない |
| 行の削除アイコン（期限の隣） | ホバーしている行にだけ出る。作ってから 1 時間未満のタスクは押すとその場で取り除く（確認は挟まない）。1 時間以上たったタスクは理由の入力欄が出て、書いてから Enter か「削除する」で取り除く（Escape・欄の外で取りやめ。ADR todo-0016）。欄の下に「渡した相手」の入力と「待ちにする」があり、名前を書いて Enter か「待ちにする」を押すと削除せず `POST /api/tasks/:id/wait` で待ちにする（理由欄に書いた文字は待ちのメモ `note` として渡す。名前が空なら送らず名前の欄にフォーカスを戻す。成功したら欄を閉じ、行を閉じて読み直し、通知「待ちへ移した」。issue #144）。Tab の順は 理由 → 削除する → 渡した相手 → 待ちにする。消したものは通知の「元に戻す」か `Cmd/Ctrl+Z` で戻る |
| タスク名（関連 URL を持つタスク） | 名前の `[N]` が関連 URL N へのリンクになる。詳細欄に関連 URL の一覧が出る（ADR todo-0014） |
| タスク名（`url` を持つ古いタスク） | 名前のうちリンクだった部分がその URL へのリンクになる。関連 URL ができる前に作ったタスクだけ（ADR todo-0008） |
| 名前にリンク付きのテキストを貼る（追加画面・開いた行） | カーソル位置に「テキスト [N]」が入り、関連 URL の [N] に URL が足される（`web/shared/static/js/paste.js`） |
| 開いた行の関連 URL | 「＋ 関連 URL」で足し、行を直す・外すとその場で保存する（`PATCH` の `links`）。名前がその番号以降を指している行は外せない |

**開くのは常に 1 行だけ**で、別の行を開くと前の行は閉じる（`state.openId`）。名前と詳細を編集できるのは開いた行の中だけで、閉じた行の名前を押しても編集には入らない。これは「行を押す＝開く」と「名前を押す＝編集」が同じ場所で競合するのを避けるためで、閉じる操作を探さなくてよくなる副作用もある（専用の閉じるボタンを置いていない理由）。

一覧は列見出しのある表で、列見出しの行（`タスク名 / 期限 / 話題 / 止まって / 状況`）は一覧の上に 1 つだけ置く（区画ごとには繰り返さない）。見出しの行から区画・行までを `.tbl` に入れ、`.tbl-scroll`（横スクロールの箱）で包む。一覧の幅が表の最小幅（810px）を下回るとこの箱の中だけが横にスクロールし、ページは動かない（390px 幅でも崩れない）。行の列は全区画で同じ `[ハンドル 10px] [チェック 18px] [タスク名 minmax(220px,1fr)] [期限 148px] [話題 120px] [止まって 64px] [状況 minmax(120px,.7fr)] [削除 22px]`（列の幅は `.tbl` の `--cols`。見出しの行も同じ）。長期（▶）・いつか（◇）の印は名前の前に置く。着手順の末尾の「＋ タスクを追加」は別の 5 列で、＋ がチェックに揃う。開いた行の詳細パネルは、セルの行の下に名前から状況の列までを使う 1 行として出る（開いた行の中は 1 行省略しない。名前の入力は折り返す）。

名前は全区画で 1 行省略（全文は `title`）。名前の先頭が `[A-Z]+-\d+` のときは、その番号を名前の左のモノスペースの札（`.tk-tag`）に分け、名前からは除いて描く。タスクのデータの名前は変えず、開いた行の名前入力は元の名前のまま（札は出さない）。リンクが番号の上から始まるタスクでは、札がそのリンクになる。チケットの札と親・子の札は、名前のテキストの先頭にインラインで置く。名前を編集している行だけ、親・子の札は名前の脇に置く。名前の `[N]` は関連 URL へのリンクのまま。

各セルの中身:

| 列 | 中身 |
|---|---|
| 期限 | 着手順・フォーカス・スコープ外の行は期限の札（押すと期限メニュー）。書き方は「今日 11/11」「明日 11/12」「11/16（月）」「11/10（火）· 1日超過」（`list.js` の `dueText`。超過の部分は API の `due_label`）。色の基準は変えない（超過=赤・今日と 1〜3 日=琥珀・それ以外は色なしで、期限が先の行の名前を薄くする。ADR todo-0011・0023）。長期の行は「見る M/D」、いつかの行は「M/D まで」、完了とやめた行は日付。**待ちの行は期限を出さず「渡して N日」**（`stalled_for`。5 日で琥珀・10 日で赤。ADR todo-0028） |
| 期限なしの警告 | 着手順とスコープ外の行で、フォーカスでなく期限が無いものは、期限の列に「⚠ 期限なし」を橙の枠と淡い橙の塗り（`.due-warn`。#9a3a00 と #fff1e6 で 6.4:1。赤・琥珀とは別の色）で常に出す。押すと期限メニューが開く。フォーカス・待ち・いつか・長期・完了・やめたには出さない（ADR todo-0028）。警告の対象にならない期限なしの行（フォーカス）は、これまで通り「期限なし」の札を行にポインタが乗っているときだけ出す |

| 止まって | 「N日」と色の段階（ADR todo-0021・0023）。列見出しが「止まって」を言う |
| 状況 | 最新の補足（`annotations` の最後の 1 件）の本文を 1 行省略で出す。無ければ空 |

ハンドル（⠿）と、警告の対象でない期限なしの行の「期限なし」の札は、行にポインタが乗っているとき・行が開いているとき・行かその中にキーボードのフォーカスがあるときだけ見える（`visibility` なので列の幅は動かない。隠れたボタンは Tab を受けないため、行にフォーカスが来てから見える）。ポインタを持たない端末（`hover: none`）では常に見える。期限のある行・期限なしの警告・長期の行の「見る」札はいつも見える。

フォーカスの帯は、薄い藍の背景だけでは周りと区別できない（背景との差は 1.2 : 1）。そのため、帯の上下の藍の線・本文の書体で太く書いた見出し（◎ と藍で塗った件数）・大きく太い行名の 3 つで区別する。線を行の左端に引かないのは、左端の 3px が期限の色に使われているため。帯を藍で塗りつぶすと、期限の琥珀・赤が読めなくなる（#86）。

カードの中は左端が 1 本（22px）。`.app-head` / `.sec` / `.add-row` の水平 padding と、行の `border-left`(3px) + `padding-left`(19px) を同じ値に保つ。行だけがカード端まで伸びるのは、色帯を縁に置くため。

todo 一覧は全幅で、サイトヘッダの上部ナビ（`.site-nav`）は出さない（ルーターが todo と todo 追加の画面を見せている間だけ `body` に `no-site-nav` を付ける。note の 2 画面では今まで通り出る）。他の画面へはサイドバーの下のリンクで行く。

画面幅が 900px 以上のときは、左からサイドバー・一覧・詳細の箱の 3 列（`.panes` の `200px minmax(0, 1fr) 360px`、間 18px）。サイドバーと詳細の箱は上部に貼り付き、一覧が残りを取る。一覧の表は最小幅 810px のまま、足りないときは表の箱の中だけが横にスクロールする。1440px 幅では一覧が 812px になり（1440 − 余白 32 − 間 36 − サイドバー 200 − 詳細 360）、表の最小幅 810px が収まる。1440px 未満では詳細の箱を 280px に狭め、一覧に幅を回す。サイドバーの幅・表の列の幅・詳細の幅のどれかを広げると、1440px で表が横にスクロールするようになる。900px 未満では詳細の箱が消え、サイドバーが一覧の上に来る（区画のボタンは横に折り返して並ぶ）。操作は開いた行のパネルにも同じものがあるので、箱が消えても失われない。

- **描画の入口**: ルーターが一覧を見せるたびに、`show` が `load()` で盤面を読み直し、`render()` が同じ `.app` へ `list.render` で描く。枠（`MARKUP`）は 1 回しか作らず、描き直しで作り直さない。状態が変わる操作（開閉・メニュー・ドラッグ・保存の応答）も `render()` を呼ぶ
- **状態の持ち方**: 状態は `app.js` の `state` 1 つ。`list.js` / `detail.js` / `menus.js` は状態を持たず、`state` と盤面（`board`）を受け取って描く。例外は `detail.js` の欄ごとの「最後に保存した文字」と保存中の印だけ（部品の中）。区画の開閉・話題で分ける設定は localStorage に残す（スコープは `week` 固定で残さない）
- **行は key で保つ**: 行は task の ID を key にするので、描き直しで変わっていない行の DOM が残る（開いた行・入力中の欄・フォーカス・CSS アニメーション）
- **入力欄は書き換えない要素（uncontrolled）にする**: 文字は要素が持ち、Preact は value も子も書かない。描き直しのたびに値を書き戻すと、ポーリングの応答や別の欄の操作で、打っている文字・フォーカス・キャレットが消える。これを次の 2 つで担保する
  - パネルと名前は、`state.busy`（欄にフォーカスがある間・ドラッグ中・メニューが開いている間）は盤面が進んでも前の task を表示したままにする（`useHeld`）。離れた後の最初の描画で追いつく
  - 外から変わった値は、欄が編集中（フォーカスがある・保存中・未保存の文字がある）でなければ欄に流し込む。編集中なら流し込まず、保存が済んでから追いつく
- **保存の仕方は欄ごとに変えない**: 名前と詳細と話題は入力が止まって 0.9 秒で保存し、欄を離れたときにも保存して読み直す。状況は Enter か「追記」で追記する。関連 URL は 1 件の変更ごとにリスト全体を PATCH し、タスクごとに 1 つずつ直列に送る。「保存中…／保存した」は `Panel` の保存印に、タスク ID を宛先にして各欄が書く。欄が取り外されるときにフォーカスが中にあれば `state.busy` を戻す（blur が来ない場合に備える）
- **関連 URL の行**: `LinksBlock` は行の持ち主（`links.create` が返す controller）を最初の描画で 1 つ作り、`LinkEditor` に渡す。持ち主は `add` / `read` / `set` / `lock` を持ち、名前の欄への貼り付け（`linkEditors[id].add`）と保存（`read(true)`）はそれを通す。外から来た一覧を行へ流し込むとき（`applied` / `seen`）は、編集中でなければ `set` で入れ替える
- **重なって出るもの**: 期限メニューと削除の理由欄は `.app` の外（画面のルート要素の直下の `.menus`）に、通知は `.flash-slot`（`display: contents`）に、`menus.js` が描く。行の中に置くと読み直しのたびに消えるため。何を出すかは `state.menu` / `state.dropAsk` / `state.flash` が決める。待ちから戻したあとの 1 行は通知ではなく待ちの区画の中（`list.js`）に描き、`state.resumed` と `state.landedId` から作る。メニューが開いている行の印（`aria-expanded`）・戻した行の色と札（`landed`、`state.resumed` があるときは「待ちから戻した」の札も）・待ちの区画に残す行（`state.resumed`）・ドラッグ中の行の薄い表示（`dragging`）・帯の「落とせる」印（`drop-ready`）も、`state.menu` / `state.landedId` / `state.drag` から描く。削除の理由欄の入力（理由と渡した相手）は書き換えない要素で、描き直しをまたいで同じ要素が残る。メニューと理由欄は位置が決まってからフォーカスを取る（決まる前に取るとウィンドウがその要素までスクロールする）
- **遅れた応答を捨てる**: `load()` は連番 `loadSeq` を持ち、遅れて届いた古い一覧の応答は捨てる。メニューと理由欄には `overlaySeq` を振り、新しく開いたものは同じタスクでも別の要素にする
- **素の JS が Preact の描いた要素を動かす唯一の例外は、ドラッグ中のプレビュー**（[#140](https://github.com/rengotaku/workbench/issues/140)）: ブラウザが掴んでいる行の要素を `app.js` の `applyPreview` が直接動かす。行をまたぐと Preact は別の要素を作り、掴んだ要素が文書から外れて `dragend` が来なくなるおそれがあるため。落とす位置は動かした要素から読み戻さず、`state.drag.dest`（`{listId, anchorId, after}`）に持つ。`render()` は描く前に `restorePreview` で要素を元の場所へ戻し、描いた後に `applyPreview` で `dest` へ動かし直すので、ドラッグ中に描き直されても落とす位置は変わらない
- `document` に付けるキー（`N`・Esc・Cmd/Ctrl+Z）とポーリングは、一覧が表示中（`active`）のときだけ動く

### todo 追加画面

todo 追加画面（`/add` と、`N`・「タスクを追加」で開くダイアログ）は `web/todo/static/js/add.js` の `AddScreen` が描く。見出し・名前・関連 URL・期限の札・詳細・追加ボタン・通知・「いま追加したもの」を持つ。

- **描画の入口**: ルーターの `mount` は部品を描かずルート要素を覚えるだけで、`show` のたびに `?parent=` と表示回数（`visit`）を渡して同じルート要素へ `AddScreen` を描き直す。ルーターが追加画面のルート要素をダイアログへ貸し出して閉じても、同じルート要素へ描き直すだけなので、部品の状態と入力の文字は残る
- **状態の持ち方**: 期限（`due`）・保存中（`busy`）・通知（`toast`）・追加した一覧（`recent`）・期限の札（`chips`）は `AddScreen` の部品の状態。関連 URL の行は `links.js` の持ち主（`rows`）が持つ
- **入力欄は書き換えない要素（uncontrolled）にする**: 名前・詳細・日付・関連 URL の各行の入力は、文字を要素が持ち、Preact は value を書かない。札・通知・行の追加と削除で描き直しても、要素・文字・フォーカス・キャレットが残る
- 関連 URL の行は key（行ごとの連番）で保つ。番号（`[N]`）と aria-label は行の並びから描くので、行を外すと残りは描き直しで振り直される。名前が `[k]` 以降を指している間は行 k を外せず、通知で知らせる。行は URL が入って入力欄を離れたときだけリンク（一言、無ければ URL）と「直す」に見え、空や http(s) でない値は入力欄のまま残る
- 送信中は名前の欄と行を disabled にし、終わると描き直しの後でフォーカスを名前へ戻す（disabled の欄にはフォーカスが入らないため、`wantFocus` で描き直しを待つ）
- 追加の応答は 1 回の送信ごとに 1 つで、送信中は `guard` で二重送信を止める（遅れた応答を捨てる連番は持たない）。`document` に付けるキー（⌥+数字・Esc）は画面が表示中（`active`）のときだけ動く

## 話題

`Task.Topic` は短い文字列（空は話題なし）で、着手順を画面で区切って見るための札（ADR todo-0024）。着手順の順序（`Order`）とは無関係で、区切りは表示だけ。

- `task.NormalizeTopic` が前後の空白を落とし、`MaxTopicLen`（20 文字。文字数で数える）と改行を検査する。`Store.SetTopic`（`PATCH /api/tasks/:id` の `topic`、`todo topic`）が設定・解除する。同じ値なら何も記録しない
- イベントは `topic_set`（`from_value` / `to_value` が新旧の話題、空は話題なし）。undo は前の話題（なしを含む）へ戻す
- 一覧の応答の `topics` は使われている話題を重複なしで返す。順序はキュー（フォーカス含む）で最初に出た順、続けて長期・待ち・いつか。話題が無ければ `[]`。画面の入力候補（`datalist`）に使う
- CLI: `todo topic <ID> <話題|->`（`-` で外す）、`todo "名前" --topic 話題`（追加してから話題を付ける。話題が不正なら何も追加しない）。`todo list` は区切らず、フォーカスと着手順の行の末尾に `{話題}` を付ける
- 画面の区切りは `list.js` の `groupByTopic`（並べる）と `groupedRows`（見出しを描く）。区切り中は `queueRow(t, true, v)` でハンドルを出さず、`app.js` の `onDragOver` が着手順への drop を受けない

## 人と AI が同時に触ったとき

書き手はサーバ 1 つで、すべての書き込みは mutex の下で直列化される。壊れることはないが、**位置の指定だけは「読んだときの順序」に依存する**ので別に守る必要がある。

- `tasks.json` に `revision` を持ち、**書き込みごとに 1 つ進む**
- 画面は 4 秒ごとに `GET /api/revision` を見て、変わっていれば読み直す（ドラッグ中・日付入力中・タブが裏のとき・別の画面を表示しているときは止める）。タブに戻った時と、別の画面から todo 一覧に戻った時も読み直す。キー操作（`N`・`Esc`・`Cmd+Z` など）も todo 一覧を表示しているときだけ受ける
- 並べ替えと、帯をまたぐドラッグ（`/focus` の `to`）は**読んだときの revision を添えて送る**。ずれていればサーバが 409（`stale: true`）で断り、画面は読み直す。黙って別の位置へ入れない
- ドラッグは drop が成立したときだけ保存する。Escape や枠の外で離したときは描き直して元に戻す
- 完了・待ち・期限・詳細の変更は revision を見ない。位置と違って、後から来た操作が勝って差し支えない（完了の二重適用は別途エラーになる）
- CLI の `todo order` は revision を送らない（自分で位置を決めて打つものなので、直前に読んだ順序に依存しない）

## フォーカス

`Task.Focused` は状態ではなく印で、着手順・待ち・完了の 3 状態とは独立。ただし**フォーカス中のタスクは着手順の先頭にまとまる**（ADR todo-0012）。

- `renumber` が着手順を「フォーカス中 → それ以外」の順に並べ直す（それぞれの中の順は保つ）。フォーカス・並べ替え・待ちからの戻り・undo のどれを通っても、この並びは崩れない。読み込み時にも並べ直す
- `FocusAt`（`POST /api/tasks/:id/focus` の `to`）は落とした位置に入れる。位置はそのタスクが属するまとまりの中に収める。`to` が無ければフォーカスの末尾、外すときは一覧の先頭
- `Reorder` はまとまりの境目を越えない。越えるのはフォーカスの付け外しで、それは `FocusAt` が行う
- フォーカスのイベントは移動前後の位置（`from_order` / `to_order`）を持ち、undo は印と一緒に位置も戻す
- API は `focus` を独立したリストとして返す（`queue` の先頭にも同じタスクが並ぶ）。画面は帯に `focus` を、一覧に `queue` のうちフォーカスでないものを出す。どのタスクも画面には 1 か所にだけ出る
- 帯は 0 件でも表示する。行をドラッグして落とす場所になるため
- 完了すると `Done` が `Focused` を落とす。帯は「次にやること」の場所なので、終わったものは残さない
- 待ちにしても `Focused` は残すが、帯には出さない。帯は「次にやること」の場所で、待ちはボールが相手にあるため。着手順へ戻すとフォーカスの末尾に戻る

## 長期

何か月もかかる仕事を置く枠（ADR todo-0019）。`StateLong` は着手順・待ち・いつか・完了と並ぶ状態で、印ではない。画面では位置ではなく条件で注意を引く（ADR todo-0022）。

- `SetLong`（`POST /api/tasks/:id/long`）は着手順のタスクだけを長期にする。長期にすると `Focused` を落とし、`review_on` が空なら今日 +7 日を入れる。外すと着手順の先頭（フォーカスのすぐ下）へ戻す。長期にした操作の undo は、入れた `review_on` も戻す
- `renumber` は長期を着手順のすぐ後ろ（待ちの前）に並べる。`openIndexes` に入らないので、並べ替え・フォーカス・待ち・いつかの対象にならない（それぞれのメソッドが断る）
- `Task.Parent` は子が持つ親の ID。長期のタスク自身は子になれない。親になれる条件と木の規則は「親子」にある
- `Task.ReviewOn`（次に見る日）と `Task.ReviewedAt`（見直した時刻）は長期のタスクだけが使う。`Review`（`POST /api/tasks/:id/review`、`todo review`）は `review_on`（省略は今日 +7 日）を置き、`ReviewedAt` を今にする。長期でないタスクには使えない。イベントは `review_set`（`from_value` / `to_value` が新旧の日付、スナップショットが元のタスク）で、undo は日付と時刻を戻す。フィールドが無い古いデータはそのまま読め、`review_on` が空の長期は「見直し日が来た」と数える
- API は `long` を独立したリストで返す。各行に `next`（未完の子のうち `Order` がいちばん小さい open のもの）と `kids_done` / `kids_open` を付ける。件数は今週に限らず全期間で数える
- 見直しが要るかは `internal/taskapi/api.go` の `longView` が決め、画面と CLI は再計算しない。次のどれかで `needs_review` が真になり、理由が `review_reasons`（この順）に入る
  - `no_next`: 未完の子が無い（`kids_open == 0`）
  - `review_due`: `review_on` が空、または今日以前
  - `stalled`: 止まっている日数が 8 日以上。長期では「見直した時刻」も人が触った印に数える（`idle_from` は `review`）
- 長期から完了にしたときは `Done` のイベントの `from_value` に `long` を残し、undo で長期へ戻す
- 画面: 長期は上部の帯ではなく、スコープ外・待ち・いつか・今週完了と同じ畳める区画の先頭（スコープ外の上）。既定は閉じ、見出しの補足は「次に見る日が来たら上に出る」。開閉は `localStorage`（`todo-order.long-open`）に残す。長期が 0 件のときは区画ごと隠す。`#T051` のように長期のタスクを指すリンクは区画を開く
- 見直しが要る長期があるときだけ、フォーカスの帯の上に「長期の見直し N」の帯を出す（無ければ帯ごと出さない）。1 件 1 行で、`!`・名前（押すと長期の区画でその行を開く）・理由の札（次の一手なし / 見直し日 M/D を過ぎた / 見直し日が未設定 / 止まって N日）・「見直した」（既定の +7 日で `review` を送って描き直す）。次の一手が無いままなら見直しても行は残る
- 長期の行は、期限チップの位置に「見る M/D (曜)」のチップを出す。押すとメニューが開く: 月のカレンダー / +1週間・+2週間・+1ヶ月（今日から）。選ぶと `review` を送る。次の一手・子の件数・止まっている日数の札・理由の札も出る
- `todo list` は長期の区画を着手順の下に出し、各行に `見る M/D` と、要見直しなら `要見直し: <理由>` を付ける。見直しが要る件数が 1 件以上なら、着手順の上に `長期の見直し N 件` の 1 行を出す

## 親子

完了していないタスクは何でも親になれる（長期・着手順・待ち・いつか。ADR todo-0020）。`internal/task/parent.go` が規則を持つ。

- 親付きで追加（`AddChild`）と `SetParent`（`PATCH` の `parent`）は、自分自身・ループ・完了済みの親を断る。木は `MaxDepth`（3）段まで。動かすタスクの子孫も数え、どれかが 4 段目になるなら断る
- 期限は子が親より厳密に前（`ErrDueRule`、HTTP 400）。確かめるのは `AddChild`・`SetParent`・子の `SetDue`・親の `SetDue`。期限を消すのは通す。完了済みのタスクは対象外
- 着手順では、同じ帯（フォーカス中 / それ以外）の中で子が親の上にいる。親が着手順に居ない（長期など）ときは掛からない。`Reorder` と、位置を指定した `FocusAt` は、規則を破る結果を `ErrOrderRule`（HTTP 409、`rule: true`）で断り、状態を動かさない。位置を指定しないフォーカスは、規則を満たす最も近い位置へ置く
- 規則が成り立つ位置への自動配置: `AddChild` は着手順の親の直上に入れて親の `Focused` を引き継ぐ。`SetParent` は子が親より下なら直上へ動かし、動かす前の位置を `from_order` に残す（undo が戻す）。`renumber` はフォーカスの並べ直しのあと、同じ帯で親より下にいる open の子を親の直前へ移す。待ちからの復帰・完了の取り消し・フォーカスの解除はここで揃う
- 親が完了や待ちになっても `Parent` は残す。画面は親の名前をそのまま出す
- API は全タスクに `parent_name` と `parent_path`（木の頂点から親までの `id` / `name`。長期の親には `long`）、子を持つなら `kids_done` / `kids_open` を付ける
- 画面は子の行に `↑` と、親の名前の先頭のチケット番号と続く空白を飛ばし、さらに子の名前（同じくチケット番号を除く）と共通する先頭部分を飛ばした後の先頭 6 文字（`parentTagText`。共通部分の切れ目は空白か `）` の直後に揃え、語の途中では切らない。飛ばして空になるときはチケット番号だけ除いた先頭 6 文字。ホバーで親の名前の全体）、子を持つ行に破線の枠で `子 完了/全体` を出す。親の選択肢は長期と着手順で、自分・子孫・深さを超える候補は出さない。規則で断られたらメッセージを出して描き直す

## 期限とスコープ

判定は `internal/taskapi` の `view` に集約されている。画面が送るスコープは `week` だけ（ADR todo-0027）。API は `scope` クエリで受け、`week`（既定）と `2weeks` は今週・来週の日曜までの日数に直す（`scopeDays`）。日数と `all` もそのまま受ける。応答の `scope_days` が実際に使った日数で、画面はこの値から境目の日付を出す。

| 条件 | `due_class` | 表示 | 件数 |
|---|---|---|---|
| 期限が過去 | `over` | 赤帯 + 赤チップ「N日超過」（7 日以上は週・月・年） | 超過 |
| 期限が今日 | `today` | 琥珀帯 + 琥珀チップ「今日」 | 今日 |
| 期限まで 1〜3 日（`taskapi.SoonDays`） | `soon` | 左端の琥珀の線（背景は塗らない）+ 琥珀チップ「M/D から」。行の文字は薄くしない | その他 |
| 期限が 4 日以降でスコープ内 | `near` | 帯なし + 灰チップ（札の文字は `dueText`）。行の文字は薄い | その他 |
| 期限がスコープ外 | `plain` | 帯なし + 灰チップ「M/D から」。行の文字は薄い。「スコープ外」の区画に出る | その他 |
| 期限なし | `none` | 帯なし。**常に表示する** | その他 |

超過の日数の単位は `taskapi.Span` が決める。6 日までは日、27 日までは週、364 日までは月（30 日。最低 1）、それより先は年で、端数は切り捨てる。期限がまだ来ていない行のラベルは日付（`fromLabel`。`11/5 から`）で、日数は出さない。札にマウスを乗せると、日付（曜日付き）とあと何日か（例: `10/30 (金)・あと7日`）が出る（ADR todo-0023）。期限なしの行には出さない。色の意味はページ下の凡例が説明する。着手順・フォーカス・スコープ外の行には、期限の色とは別に「止まって N日」の札を出す（次の「止まっている日数」）。

期限は「この日ごろに着手する」目安で、優先度は並び順で表す。色は並び順では分からないこと、つまり「着手日が来たのに、まだ上へ動かしていない」行だけに付ける（ADR todo-0011）。帯とチップは同じ基準で、画面の `dueStripe` / `dueChip` が `due_class` から決める。見出しの件数（画面の「超過 N ・ 今日 N ・ ほか N」と赤・琥珀・灰、CLI の「超過 / 今日 / その他」）も同じ区切りで数える。`soon` は「ほか」に入る。JSON のキーは `over` / `near` / `rest` のままで、`near` は「今日」の件数。

見出しの件数の下には「次の期限 M/D　<行名>」を 1 つ出す。サーバが応答の `next_due`（`due` / `id` / `name`）に、着手順・フォーカスの行のうち今日より後で最も近い期限を入れる（同じ日は着手順の先のもの。`nextDue`）。無ければ `next_due` ごと省き、画面は行を出さない。名前は先頭のチケット番号を除き、長ければ CSS で省略する。900px 未満では行ごと隠す。

期限が 4 日以上先の行（`near` / `plain`。`dueStripe` が行に `ahead` を付ける。`soon` には付けない）は、行名の文字色が一段薄い（`--ink-soft`。`--muted` は白地で 3.8:1 しかなく、名前の文字には AA の 4.5:1 に足りない）。`soon` の行は左端の線が琥珀（`--near`）になる。

期限が無いものをスコープ外にしないのは、着手順の先頭が画面から消えるのを避けるため。スコープ外の区画に入るのは「期限がスコープより先」のものだけ。

完了分は「直近の月曜以降」という**問い合わせ条件**で絞る。古い完了行をどこかへ移す処理は無い。

## 止まっている日数

忘れられているタスクを見つけるための札（ADR todo-0021）。`internal/taskapi/idle.go` が数え、画面と CLI は再計算しない（`due_class` と同じ考え方）。

- 対象は着手順（フォーカス・一覧・スコープ外）と長期。待ち・いつか・完了には付けない（待ちは自分の経過日数を持つ）
- 「触った」と数えるのは、人（`actor=human`）が書いた補足だけ。AI の補足と、並べ替え・期限・名前・フォーカスなどの操作は数えない
- 期限が今日より後の行には出さない。数え始めるのは期限の日が来てから
- 起点（暦日、サーバの今日と同じ日付計算）は、期限があれば「期限と、人の最新の補足の日のうち遅い方」、期限が無ければ「作成日と、人の最新の補足の日のうち遅い方」。今日との差が 0 以下なら何も出さない。作成日が無い古いタスクは、そのタスクの最も古いイベントの日を作成日の代わりにし、それも無ければ出さない
- 段階は 8 日以上 → 8、5 日以上 → 5、1 日以上 → 1（ADR todo-0023。todo-0021 の 2・3 は無い）。API は `idle_days`・`idle_stage`・`idle_from`（`due` / `annotation` / `created`）を、出すものがあるときだけ返す。長期の行にも付く（長期では `idle_from` に `review` も入る）
- 画面は「止まって」の列に `N日` の札を出す（読み上げには「止まって」が付く）。段階 1（1〜4 日）は枠も色も付けず文字だけ（`--muted`）、5 は紫、8 は赤（背景付き）。マウスを乗せると、どの日から数えたかが出る
- `todo list` は同じ行の末尾に `  止まって N日` を足す

## いつか

`GET /api/tasks` の `someday` は `Until`（この日までは見なくていい）の昇順で、`Until` が空のものは末尾に来る。並び順・`until_reached`（`Until` が今日以前か）の判定は `internal/taskapi` が行い、画面と CLI は再計算しない。`Until` は `Due` とは別のフィールドで、超過表示の色も件数も共有しない（ADR todo-0009）。

`shelve`（`POST /api/tasks/:id/someday`）は open か waiting のタスクを someday へ移し、`Focused` を落とす。`until` を省いた場合は今日 +1ヶ月をサーバが入れる。すでに someday のタスクに打つと `Until` だけを置き換える（`State` も `Order` も動かない）。棚卸しで先送りを決めたとき、resume してから改めて shelve する二手を踏まずに済む。`someday` からの復帰は既存の `resume`（`POST /api/tasks/:id/resume`）をそのまま使い、着手順の末尾へ戻して `Until` をクリアする。

## 取り消し

`internal/task/undo.go`。`Undo` は**イベントログを新しい順にたどり、まだ戻していない最初の 1 件の逆を当てる**。

- 逆操作は**その場で state を書き換え、イベントとして追記する**（ログは追記専用なので、取り消しは行を消すのではなく 1 行足す）
- 戻した元イベントの ID を `tasks.json` の `undone` に記録する。これが無いと 2 回目の取り消しが同じ変更を往復する
- **逆操作が書いたイベントも同時に消費済みにする**。ここを忘れると「戻す → やり直す → 戻す」の往復になる（実装中に実際そうなった）
- 削除を戻せるのは、`removed` イベントにタスクを丸ごと控えているため（`Event.Snapshot`）
- 当てられない時（対象が消えている・状態が既に変わっている）は**その 1 件を飛ばして、さらに前を探す**
- **`Resume` の取り消し**: `resumed` イベントは戻す相手を `from_value`、渡していた日を `handed_on` に持つ（`Event.HandedOn`。`omitempty`）。undo は両方を戻す。`handed_on` を持たない古い行は、相手だけ戻して日付は今日にする（読み込みの互換はこれで足りる。既存のログの書き換えは無い）。いつかからの復帰は `from_value` が空なので取り消せず、`Undo` は飛ばしてさらに前を探す
- **イベントを指定した取り消し**: `UndoEvent`（`POST /api/undo?event=<ID>`）は、次に戻される 1 件がその ID のときだけ戻し、違えば何も変えず `ErrUndoMismatch`（409）を返す。「元に戻す」を押した場所で、その間に別経路（端末）で入った変更を代わりに戻さないため。`event` が**クエリにある**のに値が空・複数指定のときは 400 で何も変えない（「直前の変更」に読み替えない。`Undo` の通常の動きは `event` が無いときだけ）。`UndoEvent("")` も `ErrUndoEventRequired` で拒否する
- **resume の応答**: `POST /api/tasks/:id/resume` は `task` に加えて `event_id`（書いた resume イベント）・`handed_to`・`handed_on`（イベントに記録した、undo が戻す値）・`revision`（書き込み後の revision）を返す（`Store.ResumeWithEvent` の `Resumed`）。ページの残し行はこの値で描き、押した時点の行の値は使わない
- **補足（`annotated`）は取り消さない**。`undoable` に入れておらず、件数にも数えない。スナップショットを書き戻す取り消し（棚上げ）は、現在の補足を書き戻し先に引き継ぐ（ADR todo-0010）

## 補足とメモからのタスク

`Task.Annotations` はタスクに足す補足で、種別は `quote`（引用）・`analysis`（考察）・`memo`（メモ）・`progress`（進んだ）・`blocked`（詰まり）の 5 つ。追記専用（`POST /api/tasks/:id/annotations`、`todo annotate`）。書き手はリクエストの `actor` で決まる。`Task.SourceNoteID` は note のメモから作ったタスクの元のメモの id で、`note route <id> --todo` が付ける。同じ `source_note_id` のタスクがすでにあれば `AddFromNote` は新しく作らず、それを返す（ADR note-0004）。人が状況を書くときは、開いた行の詳細欄の下にある 1 行の入力欄から `memo` を `actor=human` で追記する（種別は選ばせない。ADR todo-0017、todo-0018）。書きかけの本文はタスクごとに画面の state に持ち、再描画で消えない。「待ち」の種別は無く、待ちは「待ちにする」で状態を変える。画面の詳細（右の詳細ボックスと開いた行）は「状況（新しい順）」として、日時・札・本文を 1 行ずつ出し、一覧の行は補足を出さない。行にポインタを乗せると右の詳細に同じ一覧が出て、そこで読む。名前の後ろには止まっている日数の札だけが付く。札は AI が書いたもの（「AI 引用」など）と、人が書いた `quote` / `analysis` にだけ付け、人が書いた `memo` / `progress` / `blocked` には付けない。`source_note_id` があれば `/notes/timeline#note-<id>` への「元のメモ」リンクを出す。本文は `textContent` で入れ、HTML としては解釈しない。

## 理由を聞く条件

`internal/task` の `Event.NeedsReason` が判定する。次の 4 つだけで、それ以外の並べ替えは聞かない。

1. 1 位に上げた
2. 最下位へ落とした
3. スコープ内に期限があるタスクを飛び越えた（`Reorder` が飛び越えた相手を `Jumped` に記録するので自動で分かる）
4. 待ちに 14 日以上置いたまま（`Task.StalledFor` で判定）

`GET /api/ask` が未回答のものを返し、`POST /api/events/:id/why` が理由を記録する。

## 検証

`make ci` = lint（golangci-lint、govet は enable-all）+ テスト（カバレッジ）。CI は `internal/` のカバレッジが 80% を下回ると落ちる。

### E2E テスト

画面の動き（画面を移っても開いた行・スクロール位置・書きかけが残る、隠れた画面がキーに反応しない、追加ダイアログの開閉、遅れて届いた古い応答を捨てる）は `e2e/` の Go テストが確かめる。`//go:build e2e` を付けてあるので、`go test ./...` と `make ci` には入らない。

- 実行は `make e2e`。`bin/workbench-e2e` にサーバを作り、テストごとに空のデータ置き場と空きポートで起動し、API で初期データを入れる。ブラウザは chromedp で動かし、Chrome の場所は環境変数 `CHROME_PATH`（未設定なら chromedp が探す）で指定する。CI（`CI` が設定されているとき）は `--no-sandbox` を付ける
- テストは見えるもの（DOM の文字・URL・表示/非表示）だけを見る。内部の関数名や変数には触れない。画面の書き方を変えても通ることが目的
- 画面の動きを変えたら、対応するテストが落ちることを確かめてから直す
