# アーキテクチャ

現在の姿だけを書く。なぜそうしたかは `docs/adr/` にある。

## 全体

```
  人 ──┬─ ブラウザ  http://127.0.0.1:8085 ─┐
       │                                    ├─ todo-order-server ─┬─ tasks.json
  AI ──┴─ todo CLI ──── REST /api/… ────────┘   （唯一の書き手）    └─ events-YYYY-MM.jsonl
```

- **書き手はサーバだけ**。CLI もブラウザも REST を叩く。CLI はサーバが落ちていればエラーで止まり、ファイルを直接書かない
- サーバはループバック固定で認証を持たない。LAN へは出さない
- 画面はサーバ側レンダリングの 1 枚 + 素の JS。SPA もビルド工程も無い

## ディレクトリ

| 場所 | 役割 |
|---|---|
| `cmd/server/` | サーバの起動。設定読み込み・テンプレート読み込み・グレースフル停止 |
| `cmd/todo/` | CLI。サブコマンドの定義と人向けの出力整形だけを持つ |
| `internal/task/` | タスクの型・イベントの型・保存（`store.go`）・旧台帳の取り込み（`import.go`） |
| `internal/api/` | REST ハンドラ。期限の日数計算と区画分けはここで行い、画面と CLI が再計算しない |
| `internal/client/` | CLI からサーバを叩く HTTP クライアント |
| `internal/legacy/` | 旧台帳（テキストの TODO ファイルと順序 YAML）の読み取りと移行計画の組み立て |
| `internal/handler/` | 画面の配信と `/api` のマウント |
| `web/` | テンプレート・CSS・JS。`embed` でバイナリに焼き込む |
| `launchd/`, `scripts/` | 常駐させるための plist テンプレートと配置スクリプト |

## データ

`DATA_DIR`（既定 `~/.local/share/todo-order`、権限 0700）に 2 種類。

| ファイル | 性質 |
|---|---|
| `tasks.json` | 現在の状態。一時ファイルへ書いて rename で差し替える（途中状態を残さない） |
| `events-YYYY-MM.jsonl` | イベントの追記専用ログ。月ごとに分かれる |

イベントに理由を書くときも既存行を書き換えない。**同じイベント ID の新しい行を追記し、読み込み時に後の行が前の行を上書きする**。履歴そのものは編集されない。

## タスクの状態

```
        ┌──────────── resume ────────────┐
        ▼                                │
   ┌─────────┐      wait      ┌───────────────┐
   │  open   │ ─────────────► │    waiting    │
   │（着手順）│                │（相手のボール）│
   └─────────┘ ◄────────────  └───────────────┘
        │            done            │
        └──────────┐      ┌──────────┘
                   ▼      ▼
                ┌─────────────┐
                │    done     │ ── reopen ──► open（着手順の末尾へ）
                └─────────────┘
```

`Order` は 3 状態を通した通し番号で、着手順 → 待ち → 完了 の順に振り直される。画面と CLI は `Order` の昇順に並べるだけでよい。

`remove` は唯一データを失う操作。取り除いた名前と期限を `removed` イベントに書いてから消すので、**何を消したかはログに残る**。そのタスクの他のイベントは孤児として残り、読む側（`Ask` 等）はタスクが存在しないイベントを読み飛ばす。

`reopen` は完了を取り消して着手順の**末尾**へ戻す（元の位置には戻さない。その間にリストは動いているため）。完了の記録は消さず、`reopened` イベントが並ぶだけなので、経緯には「完了 → 復活」が残る。

## 画面の操作

| 操作 | どうなるか |
|---|---|
| 末尾の「＋ タスクを追加」 | 押すと入力欄になり、Enter で追加。追加後も開いたまま続けて足せる。Escape か空で離れるとボタンに戻る。位置が末尾なのは、新しいタスクが入る場所と一致させるため |
| 「今週完了」の見出し | 開閉する。既定は閉じ（記録であって待ち行列ではない）。件数は閉じたままでも出す。状態は localStorage |
| 行を押す | 詳細が開く。専用のボタンは持たない。Enter / Space でも開く |
| 詳細の中の「保存」 | 名前と詳細を更新する（PATCH） |
| 詳細の中の「待ちにする」 | 渡した相手を聞いてから待ちへ移す（相手なしでは経過日数に意味が無いため必須） |
| 詳細の中の「着手順へ戻す」 | 待ちから復帰 |
| 経緯の「理由を書く」 | その場でイベントに理由を記録する（`todo why` と同じ口） |
| 行をドラッグ | 着手順が変わる。**位置の番号は画面に出さない**（順序はリスト自体が表しており、番号は動かすたびに古くなる） |
| チェックを入れる | 完了。今週完了へ移る |
| 完了行のチェックを外す | 復活。着手順の末尾へ戻る |
| 期限チップを押す | その場が日付欄になる。空で確定すると解除 |
| 詳細の中の「削除」 | 2 段階（「戻せません。削除しますか」→ もう一度押す）で取り除く。行から 1 クリックの場所には置かない |
| タスク名のチケットキー | `TICKET_URL_BASE` を設定したときだけリンクになる |

行の列構成は 3 区画で共通: `[ハンドル] [◷（待ちのみ）] [チェック] [タスク名] [期限 or 経過]`。2 列目は待ちだけが使い、着手順と完了は空のまま列を残す（左端を揃えるため）。

カードの中は左端が 1 本（22px）。`.app-head` / `.sec` / `.add-row` の水平 padding と、行の `border-left`(3px) + `padding-left`(19px) を同じ値に保つ。行だけがカード端まで伸びるのは、色帯を縁に置くため。

## 人と AI が同時に触ったとき

書き手はサーバ 1 つで、すべての書き込みは mutex の下で直列化される。壊れることはないが、**位置の指定だけは「読んだときの順序」に依存する**ので別に守る必要がある。

- `tasks.json` に `revision` を持ち、**書き込みごとに 1 つ進む**
- 画面は 4 秒ごとに `GET /api/revision` を見て、変わっていれば読み直す（ドラッグ中・日付入力中・タブが裏のときは止める）。タブに戻った時も読み直す
- 並べ替えは**読んだときの revision を添えて送る**。ずれていればサーバが 409（`stale: true`）で断り、画面は読み直す。黙って別の位置へ入れない
- 完了・待ち・期限・詳細の変更は revision を見ない。位置と違って、後から来た操作が勝って差し支えない（完了の二重適用は別途エラーになる）
- CLI の `todo order` は revision を送らない（自分で位置を決めて打つものなので、直前に読んだ順序に依存しない）

## 期限とスコープ

判定は `internal/api` の `view` に集約されている。

| 条件 | 表示 | 件数 |
|---|---|---|
| 期限が過去・今日 | 赤帯 + 「N日超過」/「今日」 | 超過 |
| 期限がスコープ内 | 琥珀帯 + 「あとN日」 | 期限内 |
| 期限がスコープ外 | 無色。末尾に畳まれる | 外 |
| 期限なし | 無色。**常に表示する** | 外 |

期限が無いものを畳まないのは、着手順の先頭が画面から消えるのを避けるため。畳まれるのは「期限がスコープより先」のものだけ。

完了分は「直近の月曜以降」という**問い合わせ条件**で絞る。古い完了行をどこかへ移す処理は無い。

## 理由を聞く条件

`internal/task` の `Event.NeedsReason` が判定する。次の 4 つだけで、それ以外の並べ替えは聞かない。

1. 1 位に上げた
2. 最下位へ落とした
3. スコープ内に期限があるタスクを飛び越えた（`Reorder` が飛び越えた相手を `Jumped` に記録するので自動で分かる）
4. 待ちに 14 日以上置いたまま（`Task.StalledFor` で判定）

`GET /api/ask` が未回答のものを返し、`POST /api/events/:id/why` が理由を記録する。

## どこを触れば何が変わるか

| 変えたいこと | 触る場所 |
|---|---|
| 期限の表示文字・色の境目 | `internal/api/api.go` の `view` |
| 理由を聞く条件 | `internal/task/task.go` の `NeedsReason` / `AskReason`、待ちの閾値は `AskThresholdDays` |
| 画面の見た目 | `web/static/css/style.css` |
| 画面の挙動（ドラッグ・開閉・スコープ） | `web/static/js/app.js` |
| CLI の出力 | `cmd/todo/main.go`（サーバへの呼び出しは `internal/client`） |
| 保存の形 | `internal/task/store.go`。`persist` が状態、`appendEvent` がログ |
| 旧台帳の読み取り | `internal/legacy/legacy.go` |
| ポート・待ち受け・データ置き場 | `cmd/server/main.go` の `Config`（env で上書き）と `launchd/` のテンプレート |

## 検証

`make ci` = lint（golangci-lint、govet は enable-all）+ テスト（カバレッジ）。CI は `internal/` のカバレッジが 80% を下回ると落ちる。
