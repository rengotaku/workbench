# workbench

個人用の小さなローカルツールを 1 つのリポジトリ・1 つの Go モジュールにまとめたもの。

サーバは `server` 1 本（ポート 8085）で、todo と note の画面・API を同じプロセスで配る。

| ツール | 中身 | CLI | 画面 |
|---|---|---|---|
| todo-order | 着手順で持つ 1 人用の作業リスト | `todo` | `/`、`/add` |
| note-stock | 1 行メモを溜めて AI が補足するタイムライン | `note` | `/notes`、`/notes/timeline` |

API は `/api/tasks…` `/api/undo` `/api/revision` `/api/import` `/api/ask` `/api/events/:id/why`（todo）と `/api/notes…` `/api/topics…`（note）。`/healthz` は 1 つ。

## 共通の操作

```bash
make build     # bin/ に 3 本（todo, note, server）
make test      # go test ./...
make ci        # lint + テスト（カバレッジ）
make run       # サーバを起動（既定 127.0.0.1:8085。PORT=N で変更）
make status    # 起動確認
make stop      # 停止
```

配置: `cmd/` に 3 つのエントリ（`server` / `todo` / `note`）、`internal/server` が両方を 1 つの gin エンジンにまとめる、`internal/task*` / `internal/legacy` が todo-order、`internal/note*` が note-stock、`web/todo` / `web/note` が各画面、`docs/` に設計メモと ADR（`todo-` / `note-` 接頭辞）。

## todo-order

着手順で持つ 1 人用の作業リスト。**タスク名が主**で、詳細は必要なときだけ書く。順序は人が決め、見積や期限から機械的に導出しない。

人も AI も同じ `todo` コマンドを使う。CLI はローカルのサーバを叩き、サーバが落ちていればエラーで止まる（ファイルを直接書かないので、正本が二重化しない）。

### 何を持ち、何を持たないか

- 持つもの: タスク名 / 任意の詳細 / 着手順 / 状態（未着手・待ち・完了）/ 期限 / 渡した先と渡した日
- 持たないもの: Backlog 連携（取り込み・同期・親子階層）。チケットは「名前にキーが入ったタスク」として外から入れるだけで、`DSC-` のような文字列を特別扱いしない
- カンバンにしない: 管理したいのは着手順で、列は順序を表現しない。止まっているものは「待ち」1 本に出す

### 画面

| 区画 | 中身 |
|---|---|
| ヘッダー（1 行） | 名前 / 日付 / スコープ切替 / 件数（色棒 + 数字） |
| フォーカス | いま手を付けるもの。着手順の先頭にあたり、ここにだけ出る（下の一覧には出ない）。空でも出ていて、行をドラッグで入れ外しする |
| 着手順 | 1 行 1 タスク。チェック・名前・期限。上から順に取る（**見出しも位置の番号も出さない**。アプリ名がすでに「着手順」なので） |
| 待ち | 経過日数の長い順。5 日以上で琥珀、10 日以上で赤 |
| 今週完了 | 直近の月曜以降だけ取り消し線で残る。**既定は閉じている**（見出しに件数が出る） |

- **1 行 1 タスク**。**行を押すと詳細が開く**（既定は閉じている）。名前が長くても折り返さず 1 行で切る
- **追加は着手順の末尾の「＋ タスクを追加」**から。押すと入力欄になり、Enter で追加（期限は隣の日付欄で任意）。追加後も欄が開いたままなので続けて足せる。Escape か空のまま離れると元のボタンに戻る
- 位置が末尾なのは、**新しいタスクが入る場所と書く場所を一致させる**ため
- **今週完了は閉じておく**。記録であって待ち行列ではないため。見出しを押すと開き、状態はこの端末に覚える
- **編集は開いた行でそのまま**。行を開くと名前が直接編集できる（同じ位置・同じ字）。詳細も枠なしで打てて、**保存ボタンは無い**（打ち終わりと離れた時に保存され、小さく「保存した」と出る）
- **経緯は1行**。`経緯 5件` にホバーすると全部が出る（縦に伸ばさないため）。理由が未記入なら隣に「理由を書く」が出る
- **削除は期限の隣**。ホバーした行にだけアイコンが出る
- **取り消せる**。`元に戻す`（通知の中のリンク）か **Cmd/Ctrl+Z**。繰り返すとさらに前へ戻る。端末からの操作も画面からの操作も同じ順で戻せる
- **削除は 1 回押すだけ**。確認は挟まず、消したものは通知の「元に戻す」で戻る
- **完了はチェックで戻せる**。完了行のチェックを外すと着手順の末尾へ復活する。消さずにイベントとして残るので、経緯には「完了 → 復活」が並ぶ
- **カードの中は左端が 1 本**。アプリ名・区画の見出し・行の先頭・下段の説明がすべて同じ縦線に乗る
- どの区画も同じ列構成なので、行の中の縦線も揃う。2 列目はいつかの ◇ だけが使い、それ以外は空のまま列を残す
- **着手順の位置は画面に出さない**。順序はリスト自体が表しており、番号は動かすたびに古くなるだけ。位置はサーバ側で保持し、`todo order` が使う
- 行の左端の色帯: 赤 = 期限超過 / 琥珀 = 期限が今日 / 無色 = 期限がまだ先・期限なし（期限は着手の目安。ADR todo-0011）。**地色は名前の手前で消える**（文字の背景にならないように）
- **視界の制御はスコープだけ**（1 週間 / 2 週間 / すべて / 指定）。スコープから外れた分はリスト末尾に `＋ スコープ外 N件` として畳まれる
- **色の意味はホバーで出る**。ヘッダーの色棒と各行の期限チップに、いまのスコープを踏まえた説明が付く（行の左端の色帯は border なので単独でホバーできない。同じ色のチップが説明の入り口）
- **画面は自分で追いつく**。4 秒ごとに revision を見て、変わっていれば読み直す（CLI や別の窓からの変更を拾う）。ドラッグ中と日付入力中は止める
- **期限はチップを押して設定する**。メニューが開き、日付の指定・+1週間 / +2週間 / +1ヶ月・期限なし・いつかにするを同じ場所で選べる（先送りの操作を 1 か所にまとめるため）。+N は今日と今の期限の遅い方から数える。↑↓ / Enter / Esc でも操作できる
- **リンクを貼るとリンクのまま残る**。タスク名にリンクを貼ると、表示していた文字列が名前に、リンク先が `url` に入り、**貼り付け元でリンクだった範囲だけ**がリンクになる（キーだけがリンクのトラッカーならキーだけ、見出し全体がリンクの文書なら全体）。URL は貼られたまま保存し、中身は解釈しない
- **編集中もリンク範囲が見える**。編集欄の中身は 1 行のテキストのままで、範囲には色と下線だけを乗せる（CSS Custom Highlight API。非対応のブラウザでは色が付かないだけ）。貼り付け自体は常にプレーンテキストで、書式は持ち込まれない

### タスクごとの文脈

「なぜこの順番なのか」に後から答えるため、タスクごとに追記専用のイベントログを持つ。1 件 = `時刻 / 誰が（人 or AI）/ 何が変わったか / 理由`。

**並べ替えのたびに理由は聞かない。** 理由は空で記録し、次の 4 つに当たったものだけ後から聞く。

1. 1 位に上げた
2. 最下位（またはスコープ外）へ落とした
3. スコープ内に期限があるタスクを飛び越えて別を上げた（飛び越えた相手と期限をイベントに記録して自動検知）
4. 待ちに 14 日以上置いたまま

```bash
todo ask                      # 理由が空で、説明が要る変化の一覧
todo why E0012 "切替日が動いたため"   # イベントに理由を書く
todo context T004             # そのタスクの経緯を時系列で出す
```

答えなくてもよい。「理由なし」のまま残る。

### コマンド

```bash
todo "タスク名" --due 2026-09-12 [--detail "詳しい話"]  # 追加
todo list [--scope 7|14|all]                          # 一覧
todo done T007                                        # 完了（複数可）
todo reopen T007                                      # 完了を取り消して着手順の末尾へ
todo rm T007                                          # 取り除く
todo focus T007                                       # フォーカス（上部の帯）に入れる。着手順の先頭へ移る
todo unfocus T007                                     # フォーカスから外す
todo undo                                             # 直前の変更を取り消す（繰り返すと前へ）
todo wait T007 --to "相手" [--note "何を待つか"]        # 待ちへ
todo resume T007 [--note "何が返ってきたか"]            # 待ちから復帰
todo order T007 1                                     # 着手順の位置（1 が先頭）
todo due T007 2026-09-20                              # 期限（- で解除）
todo detail T007 "詳しい話"                            # 詳細を書く
todo rename T007 "直した名前"                          # 名前を変える
```

- 出力は既定が人向けの整形テキスト、`--json` で機械可読
- 存在しない ID・既完了 ID を渡したら**何も書き換えずエラーで止まる**（no-op を成功と誤認させない）
- 動詞はサブコマンドに置く。フラグに動作を持たせない

環境変数:

| 変数 | 既定 | 用途 |
|---|---|---|
| `TODO_ORDER_URL` | `http://127.0.0.1:8085` | サーバの場所 |
| `TODO_ORDER_ACTOR` | `human` | `ai` を入れるとイベントに AI として記録される |

### サーバ

todo と note で共通。起動・環境変数は「サーバ（todo / note 共通）」節を参照。

### 消すこと

`todo rm <ID>` と、行の右端（期限の隣）のアイコン。ホバーした行にだけ出て、押すとその場で消える。

- やめた作業なら `done` にするか、詳細に理由を書いて残す方が経緯が読める。`rm` は誤って追加したものを取り除くためのもの
- **削除は取り消せる**。`todo undo` か画面の Cmd/Ctrl+Z で戻る（タスクの中身をイベントに丸ごと控えてから消しているため）
- そのタスクの他のイベントはログに残ったままになる。タスクが無いイベントは読み飛ばされるので、`todo ask` / `todo context` は壊れない

### フォーカス

いま手を付けるものを上部の帯に並べる。行を帯へドラッグする、行を開いて「フォーカス」、または `todo focus <ID>`。

- **フォーカスは着手順の先頭**。フォーカス中のタスクは着手順の先頭にまとまり、帯にだけ出る（下の一覧には出ない）。優先度は並び順で表すので、フォーカスしたものが下に残る食い違いを作らない
- **ドラッグで付け替える**。一覧の行を帯へ落とすとフォーカスになり、帯の行を一覧へ落とすと外れる。どちらも落とした位置に入る。帯の中・一覧の中のドラッグは並べ替え
- 帯の行は一覧と同じ行で、**その場で開く**
- **完了すると自動で外れる**。帯は「次にやること」の場所なので、終わったものは残らない
- **空でも帯は出ている**。行を落とす場所になるため。上限は設けていない（増えれば件数で目に付く）

### 取り消すこと

`todo undo`、画面の通知に出る「元に戻す」、**Cmd/Ctrl+Z**。どれも同じ口で、**繰り返すとさらに前へ**戻る。

- 戻せるもの: 追加 / 削除 / 改名 / 詳細 / 期限 / 完了 / 復活 / 待ちへ / 復帰 / 並べ替え
- 画面の操作も端末の操作も**1 本の列**として戻る（どちらがやったかは問わない）
- **履歴は消えない**。取り消しも 1 件のイベントとして積まれる。同じ変更を 2 回戻すことはなく、2 回目は 1 つ前へ進む
- 順序を戻すときは元の位置へ入れる。その位置が無くなっていれば末尾に寄せる

### データ

| ファイル | 中身 |
|---|---|
| `tasks.json` | 現在の状態。一時ファイル + rename で原子的に書く |
| `events-YYYY-MM.jsonl` | イベントの追記専用ログ。月次で分ける |

SQLite は使わない。件数が数十で、同期機構のコストだけ払うことになるため。理由を書き込むときも既存行を書き換えず、**新しい行を追記して古い行を上書きする**（履歴を編集しない）。

### 週次スナップショット

完了分は「直近の月曜以降」という**表示条件**で絞る。完了行をどこかへ移す処理は持たない。週次の書き出しは呼ぶ側（金曜のルーティン）が読み取り専用 API を叩いて行う。

### 旧台帳からの移行

1 回だけ実行する。順序ファイルの並びがそのまま着手順になり、行に付いていたコメントは詳細として残る。

```bash
# まず書き込まずに計画を見る
todo import --ledger <旧 TODO ファイル> --order <旧 順序ファイル> --dry-run

# 問題なければ実行
todo import --ledger <旧 TODO ファイル> --order <旧 順序ファイル>
```

- 既にタスクが入っているときは**何も書き込まずに止まる**（二重取り込みを防ぐ）
- 1 行でも読めなければ書き込む前に止まる
- 旧台帳で使った番号は再利用せず、新規分はその先から採番する
- 完了済みの行も持ち込む（完了日は当日になる。過去に戻すと「今週完了」の週がずれるため）

### 常駐させる

「サーバ（todo / note 共通）」節の `make install-agent` を参照。

### 設計の記録

- `docs/todo-ARCHITECTURE.md`: 構成・データの流れ・どこを触れば何が変わるか
- `docs/adr/todo-*.md`: 覆すと影響が大きい判断の記録（カンバンを採らない / SQLite を使わない / CLI をサーバ経由に限る / 理由を後から聞く）

## note-stock

1 行のメモ（リンクと一言）を溜め、あとから AI が補足（引用・考察）と話題を足し、話題で絞ったタイムラインで読む 1 人用アプリ。

メモを書く場面ではリンクを貼って一言添えるだけにする。内容の整理は後で、アプリの外にいる AI が `note` コマンドで追記する。

### 何を持ち、何を持たないか

- 持つもの: メモ（入力した 1 行そのまま）/ メモ中の最初の URL / 任意の話題 / 追記される補足（引用・考察・メモ）
- 持たないもの
  - AI の呼び出し。アプリは AI を呼ばず、補足は外から CLI で書く
  - 補足の編集と削除。補足は追記だけで、後日の考察は日付つきで下に積まれる
  - リンク先の取得。URL は貼られたまま保存し、中身は読まない
  - 認証。ループバック（127.0.0.1）でだけ待ち受ける
- ソース表示（Slack / Notion / Backlog / リンク）は URL のホストから表示のたびに付ける。保存はしない

### 画面

| URL | 中身 |
|---|---|
| `/notes` | 登録画面。大きな 1 行入力と話題チップ、補足待ちのメモの一覧（開いた時点で読み込み、新しい順、各行に登録日時と「削除」）。Enter で保存して欄を空にし、保存したメモは一覧の先頭に足す。Esc でタイムラインへ |
| `/notes/timeline` | 日付見出しごとに新しい順。話題チップ（すべて / 最近使った 6 個 / 話題なし / 他 N）で絞り込み、右上に補足待ちの件数。「話題を整理」で話題の名前変更・統合・削除のモーダルを開く。N で登録画面へ |

- 話題は 1 つだけ選ぶ。選んだチップは保存後も残り、もう一度押すと外れる
- 話題チップは最近使った順（その話題が付いたメモの最新の登録日時）の上位 6 個のうち 1 行に入る分と選択中の話題だけを並べ、残りは「他 N」にまとめる（幅が足りなければ末尾の話題から「他 N」へ移る。幅 560px 以下は折り返して隠さない）。「他 N」と「＋ 話題を追加」は文字を打つと既存の話題が候補に出る入力欄になり（↑↓ / Enter / Esc）、候補に無い名前で確定すると新しい話題として作る。タイムラインの「他 N」は選ぶとその話題の絞り込みへ移る
- 登録画面の「✓ 保存しました」の帯は出さない。帯は保存・削除・読み込みに失敗したときだけ出る
- 話題を整理するモーダルは、話題ごとの件数を出し、名前変更・統合・削除をその行の中で確定する。既にある話題名への名前変更は統合として扱う。削除した話題のメモは話題なしになる
- 日本語入力の変換中の Enter / Esc は無視する
- 補足が 0 件のメモには「補足待ち」と出る

### タイムラインの API

`GET /api/notes/timeline` はタイムライン画面と同じ内容を JSON で返す。`?topic=<話題>` と `?no_topic=1` は画面と同じ意味。応答は `{"empty", "chips": [{"label", "href", "topic", "on"}…], "other": [「他 N」に畳む話題…], "days": [{"heading", "notes": [{"id", "time", "source", "topic", "segments", "links", "annotations", "route", "pending"}…]}…], "pending"}`。

### 話題の API

| メソッド・パス | 中身 |
|---|---|
| `GET /api/topics` | `{"topics": [名前…], "details": [{"name", "count", "last_used_at"}…]}`。`count` はその話題が付いたメモ数、`last_used_at` はその最新の登録日時（メモが無ければ null） |
| `POST /api/topics` | `{"name"}` で話題を登録（201）。応答は `GET` と同じ |
| `PUT /api/topics/{name}` | `{"name": "新名"}` で名前変更（既にある名前なら統合）、または `{"merge_into": "統合先"}` で統合（統合先は既にある話題）。どちらか 1 つだけ送る。応答は `GET` と同じ |
| `DELETE /api/topics/{name}` | 話題を消し、付いていたメモは話題なしにする。応答は `GET` と同じ |

存在しない話題は 404、不正な名前（空・同名・存在しない統合先）や項目の過不足は 400。

### コマンド

```bash
note                          # 端末から引数なし: ブラウザで登録画面を開く
note "https://… 一言"          # 引数を空白で連結して 1 件登録（--topic 青分離 で話題つき）
pbpaste | note                # 標準入力の全体を 1 件登録
note "[1] で決定" --link "https://… 一言"   # 関連 URL を添えて登録（--link を書いた順に [1] [2] …）
note list [--topic X] [--pending] [--no-topic] [--json]
note show 41 [--json]         # メモと補足を全部
note annotate 41 --kind quote --source slack --body-file quote.md
note annotate 41 --kind analysis --body "考察"
note topic 41 青分離           # 話題を設定（--clear で外す）
note topics
note delete 41
note help
```

- `--kind` は `quote`（引用）/ `analysis`（考察）/ `memo`（メモ）の 3 種。ほかは 400 で断られる
- `--author` は `ai`（既定）か `human`
- 書き込みが成功すると `note #41 追記` のような 1 行だけ出す
- サーバに届かなければ日本語のエラーを標準エラーに出して exit 1。ファイルを直接書くフォールバックは無い

| 変数 | 既定 | 用途 |
|---|---|---|
| `NOTE_SERVER` | `http://127.0.0.1:8085` | CLI が叩くサーバ |

### AI が補足を付ける流れ

```bash
note list --pending                                   # 補足待ち（補足 0 件）のメモ
note show 41                                          # 1 件を読む
note annotate 41 --kind quote --source slack --body-file quote.md
note annotate 41 --kind analysis --body-file analysis.md
note topic 41 青分離                                   # 話題が空なら AI が付ける
```

- 補足が 1 件付くと補足待ちから外れる
- あとで考え直したら `analysis` をもう 1 件足す。前の補足は残り、時刻つきで並ぶ

### データディレクトリの中身

| ファイル | 中身 |
|---|---|
| `notes.json` | 現在の状態。一時ファイル + rename で原子的に書く |
| `events-YYYY-MM.jsonl` | 操作ログ。追記だけで、月ごとに分かれる |

### サーバ（todo / note 共通）

```bash
make install        # 依存取得
make build          # bin/ に server / todo / note を出す
make run            # 起動（既定 127.0.0.1:8085。PORT=N で変更）
make status         # 起動確認
make stop           # 停止
make ci             # lint + テスト（カバレッジ）
make install-agent  # ビルド → 配置（load はしない）
```

| 変数 | 既定 | 用途 |
|---|---|---|
| `LISTEN_ADDR` | `127.0.0.1` | ループバック固定。認証は無いので LAN へ出さない |
| `PORT` | `8085` | ポート |
| `TODO_DATA_DIR` | `~/.local/share/todo-order` | todo のデータの置き場 |
| `NOTE_DATA_DIR` | `~/.local/share/note-stock` | note のデータの置き場 |
| `APP_ENV` | なし | `production` で JSON ログ・gin リリースモード |
| `SHUTDOWN_TIMEOUT` | `10s` | 停止時の待ち時間 |

旧 `DATA_DIR` は廃止した。

### 常駐させる

`make install-agent` が `~/.local/bin/workbench-server`、`~/.local/bin/todo`、`~/.local/bin/note-stock`（dotfiles の `note` ラッパーが呼ぶ名前）と `~/Library/LaunchAgents/com.user.workbench.server.plist` を置く。**読み込みは自分で行う**（login item の登録はこのマシンで監視対象のため、スクリプトからは実行しない）。

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.user.workbench.server.plist
launchctl kickstart -k gui/$(id -u)/com.user.workbench.server
curl -s http://127.0.0.1:8085/healthz
```

外すとき:

```bash
launchctl bootout gui/$(id -u)/com.user.workbench.server
rm ~/Library/LaunchAgents/com.user.workbench.server.plist
```

旧 2 サーバ（`com.user.todo-order.server` / `com.user.note-stock.server`）から移るときは、旧エージェントを bootout してから新しい方を bootstrap する（同じ 8085 を使うため）。旧エージェントの plist も消す。残すと次のログインで旧サーバが立ち上がり、データディレクトリのロックを先に取って新サーバが起動できなくなる。

```sh
launchctl bootout gui/$(id -u)/com.user.todo-order.server
launchctl bootout gui/$(id -u)/com.user.note-stock.server
rm ~/Library/LaunchAgents/com.user.todo-order.server.plist
rm ~/Library/LaunchAgents/com.user.note-stock.server.plist
```
