# todo-order

着手順で持つ 1 人用の作業リスト。**タスク名が主**で、詳細は必要なときだけ書く。順序は人が決め、見積や期限から機械的に導出しない。

人も AI も同じ `todo` コマンドを使う。CLI はローカルのサーバを叩き、サーバが落ちていればエラーで止まる（ファイルを直接書かないので、正本が二重化しない）。

## 何を持ち、何を持たないか

- 持つもの: タスク名 / 任意の詳細 / 着手順 / 状態（未着手・待ち・完了）/ 期限 / 渡した先と渡した日
- 持たないもの: Backlog 連携（取り込み・同期・親子階層）。チケットは「名前にキーが入ったタスク」として外から入れるだけで、`DSC-` のような文字列を特別扱いしない
- カンバンにしない: 管理したいのは着手順で、列は順序を表現しない。止まっているものは「待ち」1 本に出す

## 画面

| 区画 | 中身 |
|---|---|
| ヘッダー（1 行） | 名前 / 日付 / スコープ切替 / 件数（色棒 + 数字） |
| 着手順 | 1 行 1 タスク。チェック・名前・期限。上から順に取る（**見出しも位置の番号も出さない**。アプリ名がすでに「着手順」なので） |
| 待ち | 経過日数の長い順。5 日以上で琥珀、10 日以上で赤 |
| 今週完了 | 直近の月曜以降だけ取り消し線で残る |

- **1 行 1 タスク**。**行を押すと詳細が開く**（既定は閉じている）。名前が長くても折り返さず 1 行で切る
- **完了はチェックで戻せる**。完了行のチェックを外すと着手順の末尾へ復活する。消さずにイベントとして残るので、経緯には「完了 → 復活」が並ぶ
- **カードの中は左端が 1 本**。アプリ名・区画の見出し・行の先頭・下段の説明がすべて同じ縦線に乗る
- 3 区画すべて同じ列構成なので、行の中の縦線も揃う。2 列目は待ちの ◷ だけが使い、着手順と完了は空のまま列を残す
- **着手順の位置は画面に出さない**。順序はリスト自体が表しており、番号は動かすたびに古くなるだけ。位置はサーバ側で保持し、`todo order` が使う
- 行の左端の色帯: 赤 = 期限超過 / 琥珀 = スコープ内に期限 / 無色 = 期限なし・スコープ外
- **視界の制御はスコープだけ**（1 週間 / 2 週間 / すべて / 指定）。スコープから外れた分はリスト末尾に `＋ スコープ外 N件` として畳まれる
- **色の意味はホバーで出る**。ヘッダーの色棒と各行の期限チップに、いまのスコープを踏まえた説明が付く（行の左端の色帯は border なので単独でホバーできない。同じ色のチップが説明の入り口）
- **画面は自分で追いつく**。4 秒ごとに revision を見て、変わっていれば読み直す（CLI や別の窓からの変更を拾う）。ドラッグ中と日付入力中は止める
- **期限はチップを押して設定する**。その場が日付欄に変わり、空のまま確定すると解除になる（列を増やさないため、表示と入力を同じ場所に置いた）
- **チケットキーはリンクになる**。`TICKET_URL_BASE` を設定したときだけで、未設定なら素のテキストのまま。アプリはトラッカーを知らないので、これは表示だけの機能

## タスクごとの文脈

「なぜこの順番なのか」に後から答えるため、タスクごとに追記専用のイベントログを持つ。1 件 = `時刻 / 誰が（人 or AI）/ 何が変わったか / 理由`。

**並べ替えのたびに理由は聞かない。** 理由は空で記録し、次の 4 つに当たったものだけ後から聞く。

1. 1 位に上げた
2. 最下位（またはスコープ外）へ落とした
3. スコープ内に期限があるタスクを飛び越えて別を上げた（飛び越えた相手と期限をイベントに記録して自動検知）
4. 待ちに 14 日以上置いたまま

```bash
todo ask                      # 理由が空で、説明が要る変化の一覧
todo why E0012 "切替日が動いたため"   # イベントに理由を書く
todo context T004             # そのタスクの経緯を時系列で出す
```

答えなくてもよい。「理由なし」のまま残る。

## コマンド

```bash
todo "タスク名" --due 2026-09-12 [--detail "詳しい話"]  # 追加
todo list [--scope 7|14|all]                          # 一覧
todo done T007                                        # 完了（複数可）
todo reopen T007                                      # 完了を取り消して着手順の末尾へ
todo wait T007 --to "相手" [--note "何を待つか"]        # 待ちへ
todo resume T007 [--note "何が返ってきたか"]            # 待ちから復帰
todo order T007 1                                     # 着手順の位置（1 が先頭）
todo due T007 2026-09-20                              # 期限（- で解除）
todo detail T007 "詳しい話"                            # 詳細を書く
```

- 出力は既定が人向けの整形テキスト、`--json` で機械可読
- 存在しない ID・既完了 ID を渡したら**何も書き換えずエラーで止まる**（no-op を成功と誤認させない）
- 動詞はサブコマンドに置く。フラグに動作を持たせない

環境変数:

| 変数 | 既定 | 用途 |
|---|---|---|
| `TODO_ORDER_URL` | `http://127.0.0.1:8085` | サーバの場所 |
| `TODO_ORDER_ACTOR` | `human` | `ai` を入れるとイベントに AI として記録される |

## サーバ

```bash
make install   # 依存取得
make build     # bin/server と bin/todo
make run       # 起動（既定 127.0.0.1:8085）
make status    # 起動確認
make stop      # 停止
make ci        # lint + テスト（カバレッジ）
```

| 変数 | 既定 | 用途 |
|---|---|---|
| `LISTEN_ADDR` | `127.0.0.1` | ループバック固定。認証は無いので LAN へ出さない |
| `PORT` | `8085` | ポート |
| `DATA_DIR` | `~/.local/share/todo-order` | データの置き場 |
| `TICKET_URL_BASE` | （空） | チケットキーのリンク先（例 `https://example.backlog.com/view/`）。空ならリンクにしない |

## データ

| ファイル | 中身 |
|---|---|
| `tasks.json` | 現在の状態。一時ファイル + rename で原子的に書く |
| `events-YYYY-MM.jsonl` | イベントの追記専用ログ。月次で分ける |

SQLite は使わない。件数が数十で、同期機構のコストだけ払うことになるため。理由を書き込むときも既存行を書き換えず、**新しい行を追記して古い行を上書きする**（履歴を編集しない）。

## 週次スナップショット

完了分は「直近の月曜以降」という**表示条件**で絞る。完了行をどこかへ移す処理は持たない。週次の書き出しは呼ぶ側（金曜のルーティン）が読み取り専用 API を叩いて行う。

## 旧台帳からの移行

1 回だけ実行する。順序ファイルの並びがそのまま着手順になり、行に付いていたコメントは詳細として残る。

```bash
# まず書き込まずに計画を見る
todo import --ledger <旧 TODO ファイル> --order <旧 順序ファイル> --dry-run

# 問題なければ実行
todo import --ledger <旧 TODO ファイル> --order <旧 順序ファイル>
```

- 既にタスクが入っているときは**何も書き込まずに止まる**（二重取り込みを防ぐ）
- 1 行でも読めなければ書き込む前に止まる
- 旧台帳で使った番号は再利用せず、新規分はその先から採番する
- 完了済みの行も持ち込む（完了日は当日になる。過去に戻すと「今週完了」の週がずれるため）

## 常駐させる

```bash
make install-agent                                              # ビルド → 配置（load はしない）
./scripts/install-agent.sh --ticket-url-base https://example.backlog.com/view/   # リンク先も設定する
```

チケットのリンク先は**生成した plist に入り、リポジトリには入らない**。再実行時に指定を省くと、既存の plist の値を引き継ぐ。

`~/.local/bin/todo-order-server` と `~/.local/bin/todo`、`~/Library/LaunchAgents/com.user.todo-order.server.plist` を置く。**load は自分で行う**（login item の登録はこのマシンで監視対象のため、スクリプトからは実行しない）。コマンドは実行後に表示される。
