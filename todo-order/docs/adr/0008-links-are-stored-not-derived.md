# ADR 0008: リンクは貼られたものを保存する。名前から組み立てない

## 背景

タスク名の中の `ABC-1234` のような文字列を拾い、`TICKET_URL_BASE` と連結してリンクにしていた。1 つのトラッカーだけを使い、その ID の形が決まっている限りは動く。

動かない場面は 3 つある。別のスペースや別のトラッカーのリンクを貼ると、キーの形が同じというだけで設定側のベースへ飛ばされる。ID の形が違うサービス（wiki やドキュメント）のリンクは、そもそもリンクにならない。そして貼り付けの時点で URL を捨てているので、間違った飛び先になっても直す材料が残らない。

つまり**貼られた事実（この名前はこの URL から来た）を捨て、名前の見た目から推測で復元していた**。推測が当たるのは、特定の SaaS を前提に置いたときだけになる。

## 決定

タスクに `url` を持たせ、貼り付けたリンクの `href` をそのまま保存する。表示は `url` があればそこへ飛ばし、無ければ素のテキストにする。

- URL は解釈しない。ホスト名も ID の形も見ないので、トラッカー・wiki・ドキュメントの区別がそもそも存在しない
- 名前からリンクを組み立てる経路は消す。`TICKET_URL_BASE` と、そのための正規表現も一緒に消す
- 貼り付けの本文は、アンカーの中身ではなくクリップボードの HTML 断片全体のテキストから取る（キーだけをリンクにし、タイトルを隣に置くコピー形式があるため）
- リンクを張る範囲は `link_text`（貼り付け元でアンカーだった文字列）に限る。「リンクだった部分がリンクのまま残る」という規則だけを持ち、どこがキーかは判定しない
- 編集中の名前は 1 つのテキストノードのまま保ち、リンク範囲は CSS Custom Highlight API で塗る。編集欄に `<a>` を置くとクリックでの遷移・ドラッグ・キャレットの吸い込みが起き、DOM を塗り替えるとキャレットが飛ぶため、どちらも起こさない方法を採った

## 捨てた案

**`url` を持たせつつ、無いものはキーから補う**。移行が楽に見えるが、特定のサービスの ID 形式を前提にしたコードが残り続ける。残せば必ずそこに例外が積まれるので、消した。既存タスクのリンクはこの決定で失われる（名前のテキストは残る）。貼り直せば戻る。

**貼り付けを HTML のまま保存する（リッチテキスト）**。リンクを完全に再現でき、編集中の見た目も自然になるが、名前が値から文書に変わる。1 行のテキストという前提の上に CLI の表示・イベントログの差分・検索・比較が乗っているため、そのすべてがタグを剥がす前提になる。外部の HTML を取り込む以上 sanitize も要る。得られるのは見た目だけで、それは Highlight API で足りる。

**編集中の名前にも `<a>` を置く**。見た目は一致するが、リンクの上でクリックすると遷移し、ドラッグで持って行かれ、端でタイプすると中に吸い込まれる。

## 前提

- 変えてよい: リンクの見た目（名前全体をリンクにしているが、アイコンにしてもよい）
- 壊すと危ない: `url` を解釈し始めること。ホストや ID の形で分岐を入れた時点で、この ADR は無効になる
