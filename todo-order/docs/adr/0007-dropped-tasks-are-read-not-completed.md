# ADR 0007: やめたタスクは完了にせず、週の記録として読ませる

## 背景

削除するときに理由を残したい、という話から始まった。最初に出た案は「理由付きで消したものは完了として残す」だったが、これは 2 つの意味を 1 つの状態に載せることになる。完了は片付いたもの、やめたものは片付かなかったもので、混ぜると「今週やった件数」に、やっていない件が混じる。

もう一方で、`removed` イベントは以前から名前とスナップショットを書いていた（ADR 0002 の追記専用ログ）。つまり**書く場所は既にあり、読む経路だけが無かった**。理由を足しても、読めなければ書き捨てになる。

## 決定

3 つに分ける。

**状態は増やさない。** 未着手・待ち・完了の 3 つのまま。やめたタスクは `tasks.json` から消え、イベントログの中だけに残る。画面に出る「今週やめた」はログから組んだ読み取り専用のビューで、第 4 の状態ではない。

**理由はクリック時に聞かない。** 削除は 1 クリックのまま（確認もテキスト入力も挟まない）。`Reason` は空で記録し、`NeedsReason` の対象に `removed` を足して**後から質問キューで聞く**。これは並べ替えについて ADR 0004 が決めたことを、そのまま削除へ広げたもので、新しい方針ではない。答えなくてもよく、「理由なし」のまま残る。

**読む場所は「今週完了」の隣。** 同じ `fold-head` の畳み区画をもう 1 本、既定は閉じ、件数だけ出す。週の終わりに開くと、片付けた件とやめた件が並んで見える。絞り込みは完了と同じ「直近の月曜以降」で、ディスク上では何も動かさない。

取り消した削除は一覧に出さない。タスクが戻っている以上やめていないため。「追加」を取り消したときに undo が書く `removed` も同じ理由で出さない（undo の副産物であって、やめる判断ではない）。

## 捨てた案

- **理由付きの削除を完了として残す**: 完了の実績に、やらなかった件が混じる。「今週 N 件終わった」が意味を失う
- **削除時にモーダルで理由を聞く**: ADR 0004 が並べ替えで捨てたのと同じ理由。直前のコミットでわざわざ確認を外した削除に、入力を戻すことになる
- **`todo context <ID>` を消えたタスクにも効かせる**: 読めるようにはなるが、**消したタスクの ID は誰も覚えていない**。引けない読み口は無いのと同じ
- **`todo log` のような一覧コマンドを新設する**: 打とうと思った人しか読まない。週の終わりに目に入るのは画面の方

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: 区画の切り出し方（週 → 任意の期間）、並び順、理由を聞く文言、`Drop` に載せる項目
- **壊すと危ない**: 削除の理由を**必須にしないこと**。必須にすると、消すのをやめて放置する方が楽になり、リストが腐る
- **壊すと危ない**: `removed` イベントに `Snapshot` を書き続けること。名前も期限も、消えたあとはここにしか無い。undo（ADR 0006）も同じスナップショットに依存している
- **壊すと危ない**: 取り消し済みの削除を除くこと。除かないと、同じタスクが着手順と「今週やめた」の両方に出る
